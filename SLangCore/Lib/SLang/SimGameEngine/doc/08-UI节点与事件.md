## 1. UI 节点模型

UI 也是普通 GameObject，只是挂的组件不同：

```
GameObject "Button"
  ├─ RectTransform          ← 替代普通 Transform（但仍继承自 Transform）
  ├─ UIBehaviour 子类       ← 指针 / 点击 / 拖拽钩子
  └─ Renderer + MaterialRef ← 走 2D QUAD 批次（第 05 章）
```

三条规则：

1. **UI 节点只用 RectTransform**，不混用普通 Transform 的 3D 语义；
2. **UI 独占一个 layer**，主相机的 cullMask 不含该 layer，避免 UI QUAD 被 3D 相机重复收集；
3. **UI 不参与 3D 合批**：它走独立的 QUAD 批次，按屏幕空间层级顺序提交（Render 只提供 2D 绘制路径，不做完整 UI 布局系统）。

## 2. UIBehaviour【已落盘】

源码：`../UIBehaviour.sl`，`extends Behaviour`，因此具备第 02 章全部生命周期钩子。

### 2.1 字段

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `rectTransform` | `RectTransform` | null | 关联的矩形变换；**必须赋值**才能做命中检测 |
| `raycastTarget` | bool | true | 是否参与 UI 射线命中 |
| `interactable` | bool | true | 是否可交互 |

### 2.2 事件钩子（子类 override）

| 签名 | 触发时机 |
|---|---|
| `void onPointerEnter()` / `void onPointerExit()` | 指针进入 / 离开 |
| `void onPointerDown(Float32_2 position)` / `void onPointerUp(Float32_2 position)` | 按下 / 抬起 |
| `void onClick(Float32_2 position)` | 点击 |
| `void onDrag(Float32_2 delta)` | 拖拽，`delta` 为屏幕空间位移 |
| `void onScroll(Float32 delta)` | 滚轮 |
| `void onSelect()` / `void onDeselect()` | 选中 / 取消选中 |

### 2.3 命中与状态方法

| 签名 | 说明 |
|---|---|
| `bool hitTest(Float32_2 position)` | 点是否落在矩形内（委托 `rectTransform.hitTest`）；内部先检查 `rectTransform`，为 null 直接返回 false |
| `void setInteractable(bool value)` | 切换可交互状态 |
| `override string toString()` | `UIBehaviour(raycast=..., interactable=...)` |

## 3. RectTransform【已落盘，SLangRender】

源码 `RectTransform.sl`（SLangRender 根级，`extends Transform`）。**2026-11-17 随 Transform 统一版迁回 SLangRender**：Transform 统一合并后引擎自有同名类删除，P5 时的跨模块同名继承链断点（双模块各有一个 `Transform`）已消失，同模块继承成立；引擎侧 `UIBehaviour`/`UISystem` 经 `import SLangRender` + slb 引用消费，API 面不变（成员表同前）。

| 成员 | 说明 |
|---|---|
| `Float32_2 anchoredPosition` | 相对锚点的位置 |
| `Float32_2 sizeDelta` | 相对锚点区域的尺寸偏移 |
| `Float32_2 anchorMin` / `anchorMax` | 锚点范围，归一化 [0,1] |
| `Float32_2 pivot` | 轴心，归一化 [0,1]，默认 (0.5, 0.5) |
| `get Float32 width` / `get Float32 height` / `get Float32_2 size` | 尺寸读取 |
| `get Float32_2 topLeft` | 以 pivot 反推的左上角位置 |
| `void setSize(Float32_2 size)` / `void setSize(Float32 w, Float32 h)` | 设置尺寸 |
| `void setAnchoredPosition(Float32_2 pos)` / `void setPivot(Float32_2 p)` | 设置位置 / 轴心（pivot 钳制到 [0,1]） |

| `bool hitTest(Float32_2 point)` | 点是否落在矩形范围内 |

## 4. 事件分发流程【已落盘 2026-11-16 P5：`system/UISystem`】

```
宿主输入系统给出屏幕点 (x, y)
  │
  ├─ 1. UISystem.pick(scene, x, y)：显式栈前序遍历，raycastTarget=true
  │     且 rectTransform 已赋值的 UIBehaviour 做 hitTest；同点多命中时
  │     后绘制者（树序靠后）获胜
  ├─ 2. dispatchPointerMove：进入/离开 → onPointerEnter / onPointerExit
  │     （interactable=false 仍派发）
  ├─ 3. dispatchPointerDown：onPointerDown(pos) + 选中切换 onSelect/
  │     onDeselect（interactable 门控 Down 与 Select；旧选中 Deselect 不门控）
  ├─ 4. dispatchPointerUp：onPointerUp(pos)；同体抬起追加 onClick(pos)
  ├─ 5. dispatchDrag(dx,dy)（按住期间）/ dispatchScroll(delta)（发给 hovered）
  └─ 6. 事件钩子全部经 SystemSimEngineCallHook/CallHook1 按名派发到
        最派生 override（跨模块 slb CallVirt 不派发消费方 override）
```

`raycastTarget = false` 的节点仍可显示，但不参与命中（适合纯装饰图文）。`interactable = false` 的节点仍参与 Enter/Exit 视觉反馈与按压状态跟踪（`pressed` 会置位），但不触发 Down/Up/Click/Drag/Scroll/Select。各 dispatch 方法返回本次派发的事件数（Int32），可用于宿主侧「UI 是否消费了事件」判定（消费后再决定是否做 3D 世界拾取）。

## 5. UI 批次与绘制

| 行为 | 做法 |
|---|---|
| 网格 | 用 `pipe.MESH_QUAD`（Render 已提供） |
| 材质 | UI 专用 Material；贴图经 `setTexture` 或 Material 带入 |
| 位置缩放 | 屏幕空间坐标 → 写入 RenderObject 的 `setPosition` / `setScale`；Z 旋转用 `setRotationZ` |
| 排序 | 按 UI 树层级顺序提交；后绘制的在上 |
| 合批 | 同一 UI Material + 同一贴图的 QUAD 可合批；不同贴图拆批（建议用图集） |
| 相机 | UI layer 独立，主相机 cullMask 不含该 layer；专用 UI 相机单独渲染 |

## 7. 已知坑与注意

1. **`rectTransform == null` 时命中检测静默失败**：`hitTest()` 显式判空返回 false，不会报错；界面「点不动」先查这个赋值。
2. `Float32_2` 是 UI 空间类型，来自 `import Math;`；不要把它和世界空间 `Float32_3` 混用。**源文件用到 Math 类型（含方法参数）必须文件头 `import Math;`**——缺 import 时 Float32_2 参数方法整体注册失败（`…没有在类[…]中被发现`），已实证（doc/10 §6）。
3. UI 事件钩子与 `Behaviour` 生命周期共用一套 `isEnabled` 开关；组件被禁用时钩子不再触发。
4. 拖拽 `onDrag` 的 `delta` 是**屏幕空间位移**，不是世界位移；做 3D 物体拖拽须经相机反投影。
5. UI 走 QUAD 批次，不进 3D 合批键体系；把 UI 节点误挂到 3D layer 会被主相机收集并画在错误位置。
6. `UISystem` 是普通类（非单例）：`hovered/pressed/selected` 状态在实例上，宿主每帧用同一个实例调用 dispatch 系列；换实例会丢悬停/按压状态。
7. 事件计数语义：`dispatchPointerMove` 换目标时 Exit+Enter=**2**；`dispatchPointerDown` 对非 interactable 目标仍发旧选中 `onDeselect`（=1）——按事件数断言时注意（SimAnimTest AN9 同款）。

## 8. UI 画布管理节点与两种渲染模式【已落盘 2026-11-19】

> 对标 Unity `Canvas` 的 `RenderMode` + URP/HDRP 的 Camera Stack：UI 既能「系统合成到屏幕最上层」，也能「挂到管理节点上、指定相机、相机输出在引擎层按图层叠加」。源码 `ui/UICanvas.sl` + `system/UICanvasSystem.sl`，测试 `SimUICanvasTest`（50 项）。

### 8.1 两种模式

| `renderMode` | 常量 | 语义 | 是否需要赋值相机 |
|---|---|---|---|
| 0 | `UICanvas.MODE_SCREEN_OVERLAY` | **系统叠加层**：引擎自动挂专用 UI 相机（layer 31、depth 10、`clearFlags=2` 只清深度），UI 网格交给 `FairyUIRenderer`/`submitUiMeshTex` 提交，天然盖在 3D 画面之上。与 Unity `Screen Space - Overlay` 对应。 | 否 |
| 1 | `UICanvas.MODE_CAMERA` | **相机赋值层**：在管理节点上指定 `camera`，引擎层按 `sortingOrder` 把它编排进相机栈（`depth = 20 + sortingOrder`、`cullMask = 1<<uiLayer`、`clearFlags` 默认 2 = 保留上一相机颜色 → 相机处理完成后做图层叠加）。与 Unity `Screen Space - Camera` + Overlay Camera 对应。 | 是 |
| 2 | `UICanvas.MODE_WORLD` | **世界空间层**：同上但相机 `extents` 按 `referenceWidth/Height ÷ scaleFactor` 换算成世界单位，UI 节点走普通 `Transform` 摆放。与 Unity `World Space` 对应。 | 是 |

### 8.2 UICanvas 字段

| 字段 | 默认值 | 说明 |
|---|---|---|
| `Int32 renderMode` | 0 | 渲染模式，见上表；setter 拒绝越界值并写 `lastError` |
| `SLang.RenderCamera camera` | null | 相机模式的目标相机；`hasCamera()` 判有效性 |
| `Int32 uiLayer` | 31 | 画布独占渲染层；模式 0 由引擎强制回 31 |
| `Int32 sortingOrder` | 0 | 相机栈排序号，越小越先画 |
| `Float32 planeDistance` | 5.0 | 世界空间平面距离（预留给布局换算） |
| `Float32 referenceWidth/Height` | 1280/720 | 设计分辨率（世界空间 extents 换算基准） |
| `Float32 scaleFactor` | 1.0 | 缩放系数 |
| `Int32 clearFlags` | 2 | 叠加清屏位：1=颜色 / 2=深度 / 3=全部。默认只清深度即保留底图 |
| `bool pixelPerfect` | false | 像素完美开关（供宿主布局消费） |

### 8.3 引擎层流程（`UICanvasSystem`）

```
Systems.setupCanvas(scene)
  ├─ canvas.collect(scene)：显式栈遍历 → 激活节点取 UICanvas →
  │    按 (renderMode 升序, sortingOrder 升序, 树序) 稳定排序
  └─ canvas.configure(render)：逐画布落相机参数
        mode0 → RenderSystem.ensureUiCamera()（系统相机，layer 31/depth 10）
        mode1 → 赋值相机 setCullMask(1<<layer)/setDepth(20+order)/setClearFlags
        mode2 → 同上 + setExtents(±refW/(2s), ±refH/(2s))
  ↓
Systems.frame(time, dstPtr)：管线按 depth 升序逐相机绘制；
  clearFlags=2 的相机不清颜色 → 上一个相机的输出被保留 → 图层叠加完成
  ↓（需要把某相机的输出作为独立图层再合成时）
Systems.compositeLayer(dstPtr, layerPtr, w, h, alpha, mode)
  → C sle_layer_composite（ALPHA / ADD / MULTIPLY，alpha 钳 [0,1]）
```

### 8.4 使用示例

```sl
import SimGameEngine;
import SLangRender;

Systems sys = Systems()
sys.init( 1280, 720 )
# —— 模式 0：系统叠加（只需一个管理节点，无需相机）——
GameObject hud = scene.createObject( "HUD" )
UICanvas hudCanvas = UICanvas()
hud.addComponent( hudCanvas )        # 默认 MODE_SCREEN_OVERLAY

# —— 模式 1：相机赋值 + 图层叠加 ——
SLang.RenderCamera uiCam = sys.render.pipe().addCamera( 0 )
GameObject panel = scene.createObject( "PanelCanvas" )
UICanvas cv = UICanvas()
cv.setRenderMode( UICanvas.MODE_CAMERA )
cv.setCamera( uiCam )
cv.setLayer( 30 )
cv.setSortingOrder( 3 )
cv.setClearFlags( UICanvas.FLAGS_DEPTH )   # 只清深度 = 盖在主相机颜色之上
panel.addComponent( cv )

# 每帧：sync → setupCanvas → frame
sys.sync( scene, time )
sys.setupCanvas( scene )
sys.frame( time, dstPtr )

# 独立图层叠加（把另一相机/离屏管线的输出合成到主帧）
sys.compositeLayer( dstPtr, otherCamBuffer, 1280, 720, 1.0f, UICanvasSystem.BLEND_ALPHA )
```

### 8.5 已知边界与坑

1. `configure` 必须在 `renderFrame` 之前调用——相机参数写定后本帧剔除/绘制才一致（`setupCanvas` 已固定放在 `sync` 后、`frame` 前）。
2. 模式 1/2 未赋值（或相机失效）的画布不会崩：`configure` 跳过并把原因写进该画布 `lastError`。
3. 图层叠加的 `dstPtr`/`layerPtr` 都是 top-down RGBA8（`w*h*4`），像素数须与 `w*h` 一致，否则 C 核心返回码不等于像素数、`composite` 判失败。
4. 当前管线所有相机共享同一 `rt_scene`（无 per-camera FBO）；「图层叠加」靠 `depth` 升序 + `clearFlags=2` 不清颜色实现，与 Unity Overlay Camera 语义一致。若需要「相机输出独立纹理再回贴」，走 §8.4 的 `compositeLayer`（先各自出帧到 RGBA8 块，再 C 合成）。
5. 常量是 `static` 字段，作实参时先落局部变量（如示例中的 `cv.setRenderMode( UICanvas.MODE_CAMERA )` 为直接赋值可用；方法间传递请先 `Int32 m = UICanvas.MODE_CAMERA`）。
