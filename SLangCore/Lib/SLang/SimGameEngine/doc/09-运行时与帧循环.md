## 1. Application【设计稿】

`Application` 是引擎的入口门面，负责建场景、起循环、收尾销毁。拟定接口：

```sl
public class Application
{
    public Scene  activeScene
    public bool   paused
    public Float32 timeScale           # 默认 1.0

    public bool init()                 # 初始化 Render 后端 + 建默认 Scene
    public void tick( Float32 dt )     # 一帧；由宿主计时器 / 主循环调用
    public void shutdown()             # 销毁场景、RenderObject、Render 后端

    public void loadScene( Scene s )   # 旧场景帧尾销毁，新场景下一帧生效
}
```

宿主可以是 QT 窗口（现有 RenderTest 路径），也可以是命令行 / 无头循环（CI、烘焙）。引擎层不绑定具体窗口系统。

## 2. 一帧的 11 个步骤

与 `01-总体架构与边界.md` §4 完全一致，这里是带规则的展开版：

| # | 阶段 | 做什么 | 失败 / 跳过规则 |
|---|---|---|---|
| 1 | 时间推进 | `dt = min(rawDt, maxDt) * timeScale`；`paused` 时 dt = 0 | 防止切后台回来一帧巨量 dt |
| 2 | 输入采样 | 收集指针 / 按键，先给 UI 命中（第 08 章），未消费再给世界拾取 | UI 消费后停止下传 |
| 3 | fixedUpdate ×N | 固定步长累加器，`while acc >= fixedDt` | 单帧最多 N 次，防螺旋死亡 |
| 4 | `Behaviour.update` | 按树序父先子后 | `isEnabled=false` 或 `activeInHierarchy=false` 跳过 |
| 5 | `Behaviour.lateUpdate` | 相机跟随、后处理参数 | 同上 |
| 6 | 变换刷新 | 脏节点自顶向下重算 localToWorld | 未被写脏的节点沿用上次结果 |
| 7 | 可见性收集 | active + layer & cullMask + Bounds 粗筛 | 不进候选就不产生 RenderObject |
| 8 | 合批与写入 | 第 05 章：BuildKey → 聚组 → uploadMesh → RenderObject 字段 | 同键才合批 |
| 9 | 相机 / 灯光下发 | `pipe.setCamera(...)`、`light.applyTo(pipe, slot)` | 超灯光槽的光源本帧丢弃 |
| 10 | 渲染 | `pipe.renderFrame(t, dstPtr)` 或 `pipe.runStages(t, dstPtr)` | 回读缓冲 dstPtr 由调用方分配 |
| 11 | 帧尾 | 统计、延迟销毁 `dispose()`、RenderObject 归还池 | 本帧内仍可安全读待销毁节点 |

**步骤 8 必须在 6 之后、10 之前**：先有最终变换，才能烘焙顶点；先写完 RenderObject，管线才开始 13 阶段。

## 3. QT 计时器驱动【已落盘写法】

RenderTest 已验证的主循环骨架：

```sl
import SLangQT;
import SLangRender;

SLang.QApplication app = SLang.QApplication()
SLang.QLabel label = SLang.QLabel( "SLangRender demo", 296, 372 )
label.show()

SLang.QTimer timer = SLang.QTimer( 16 )             # ~60 fps
timer.timeout( RenderTest.onTick )
app.exec()                                          # 进入事件循环
```

`onTick` 内部（RenderTest.sl 的既有写法）：

```sl
# 1) 更新动画时间
_t = _t + 0.016f

# 2) 跑 13 阶段并回读 RGBA8
_pipe.runStages( _t, _pixels )

# 3) 上屏
_label.setPixmapRgba( _pixels, _texW, _texH )
```

接入引擎时，把 `onTick` 的第 1 步换成 `app.tick(0.016f)`：`tick` 内部走完 §2 的 11 步，`pipe.renderFrame` 的结果写进 `_pixels`，再交给 label 上屏。定时器间隔与 `dt` 要一致，否则动画速率与真实时间不符。

## 4. 固定步长累加器【设计稿】

```sl
Float32 fixedDt = 1.0f / 60.0f
Int32   maxSteps = 5

acc += dt
Int32 steps = 0
while acc >= fixedDt && steps < maxSteps
{
    foreach component : allBehaviours
    {
        component.fixedUpdate()
    }
    acc -= fixedDt
    steps++
}
if steps == maxSteps
{
    acc = 0.0f            # 丢弃积压，防螺旋死亡
}
```

`timeScale` 只缩放 dt；固定步长本身保持 `fixedDt` 不变，缩放体现在一帧内执行的步数上。

## 5. 暂停、场景切换与销毁

| 场景 | 行为 |
|---|---|
| `paused = true` | dt = 0：update / fixedUpdate 不再推进；相机与渲染照常执行（画面静止但仍刷新） |
| `loadScene(s)` | 旧 Scene 标记销毁，新 Scene 下一帧起进入帧序；旧 Scene 的 RenderObject 在旧帧帧尾回收 |
| `destroy()` | 节点立即标记、组件立即 `onDisable()`；`dispose()` 在帧尾第 11 步统一调用 |
| `shutdown()` | 先停计时器 → 销毁所有 Scene → `pipe.destroy()` → `Render.uninitialize()` → 释放回读缓冲 |

不要在 `update()` 里直接 `Memory.free` 正在被管线引用的回读缓冲；释放放到帧尾，与 RenderObject 回收同一时机。

## 6. 完整骨架示例（设计稿 + 已落盘混合）

```sl
import Std;
import Math;
import SLangQT;
import SLangRender;

SLang.QApplication app = null
SLang.QLabel label = null
SLang.RenderPipeline pipe = null
Int64 pixels = 0
Int32 w = 296
Int32 h = 372
Float32 clock = 0.0f

public static bool boot()
{
    if !SLang.Render.initialize()
    {
        Console.println( SLang.Render.errorString() )
        ret false
    }
    app = SLang.QApplication()
    label = SLang.QLabel( "SimGameEngine", w, h )
    label.show()
    pipe = SLang.RenderPipeline.create( w, h )
    pixels = Memory.alloc( w * h * 4 )
    ret true
}

public static void onTick()
{
    Float32 dt = 0.016f
    clock += dt

    # 引擎层：app.tick(dt) 内部完成 §2 的 1~9 步与合批
    # app.tick( dt )

    pipe.renderFrame( clock, pixels )                # 第 10 步
    label.setPixmapRgba( pixels, w, h )              # 上屏
    # 第 11 步：帧尾回收由 app.tick 收口
}

public static void stop()
{
    pipe.destroy()
    Memory.free( pixels )
    SLang.Render.uninitialize()
}
```

```sl
SLang.QTimer timer = SLang.QTimer( 16 )
timer.timeout( onTick )
app.exec()
```

> 说明：`boot/onTick/stop` 与 QT 初始化是 RenderTest 已验证的调用形态；仅 `app.tick(dt)` 属于第 09 章设计接口（`Application` 尚未落盘），落地前需按实际 API 调整。

## 7. 已知坑与注意

1. **后端切换全量重建**：切换 gl / d3d11 / vk / gles 后，管线、纹理、RenderObject 句柄全部失效；先 `shutdown()` 再按 §6 重建，不要只换后端字符串。
2. `QTimer(16)` 是近似 60fps，不是精确 16ms；`dt` 建议用真实时间间隔计算，并做上限裁剪。
3. `app.exec()` 是阻塞事件循环，退出前要先停 timer 再 `shutdown()`，避免回调访问已销毁的管线。
4. `runStages` 与 `renderFrame` 等价但逐阶段驱动；调试可用前者，正式循环用后者。
5. 暂停时不要跳过渲染：状态变化（如 UI 提示）仍需上屏；停的是逻辑推进，不是画面刷新。
6. 延迟销毁意味着 `destroy()` 后同一帧内仍可能读到该节点；需要立刻不可见时先 `setActive(false)` 或 `setVisible(false)`。
7. 渲染回读缓冲 `pixels` 是 RGBA8，`w*h*4` 字节，由调用方分配和释放；QT 上屏走 `label.setPixmapRgba(pixels, w, h)`。
