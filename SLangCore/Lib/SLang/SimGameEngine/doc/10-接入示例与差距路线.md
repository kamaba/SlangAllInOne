## 1. 工程接入

### 1.1 依赖组合（RenderTest 已验证）

工程 `.jsonc` 的 `references` 段：

| 模块 | 版本 | 用途 |
|---|---|---|
| `SLangQT` | 0.1.0 | 窗口 / 计时器 / 上屏（无窗口程序可省） |
| `SLangRender` | 1.0.0 | 渲染门面 + 原生库 + RectTransform |
| `Core` / `Std` / `Math` | 随官方库 | `Component` 来自 Std 根级；向量 / 矩阵来自 Math |

可选：`SLangImage 1.0.0`（贴图加载，需 `import SLangImage;`）。

**测试目录说明**：`test/` 各子目录为独立测试工程（.sl/.jsonc/.sp 三件套），引用导出的引擎 slb + Core/Std/Math（**相对路径 4 级** `../../../../Lib/`）+ Render/Audio（**绝对路径** `D:/project/lang/...`——模块 slb/jsonc 引用相对解析实测在 >4 级目录下不可靠，audioFixture/Tensora 绝对兜底先例）；运行 CWD = SlangAllInOne。

产物按全仓规则写入 `SlangAllInOne/out/export/SimGameEngine/`（`slang compile <模块>.sp --format binary` 落盘；裸路径运行只出内存包）。**消费方必须引用导出的 `SimGameEngine.module.slb`**：路径引用源码 jsonc 只注册类型名、不带成员元数据（成员解析全部失败）。引用链不透传：消费方还需显式引用 Core/Std/Math（不可 `import Core`，只引用）。

**引用顺序规则（2026-11-16 实证，`SimModuleTest`）**：`references` 列表中 **Core/Std/Math 必须在最前**——后续引用模块的跨模块静态方法签名 mangle 依赖基础类型元数据先注册，顺序不对时参数类型一律错 mangle 成 `Core.Object`（IR not found；P2 坑⑦的根因）。Render/Audio 等模块引用放其后。

**双模块同名专项（2026-11-17 进一步消解）**：`Transform`/`RectTransform` 已统一合并入 SLangRender（引擎自有类删除，全仓复用统一版）；引擎仅剩 `Ray`/`Material` 与 Render 同名，仍按模块作用域隔离共存（裸名解析到引用序靠前的模块版）。消费形态：
- 引擎类照常（Scene/GameObject/Transform/collider）；
- Render：`Vertex`（实例方法 `transformed` 可喂引擎 `worldMatrix()` —— 交叉复用）、根级 `Vector`/`Material`/`Shader`/`Texture`、门面 `SLang.Render`；
- Audio：namespace 限定 `Audio.AudioIO`/`Audio.AudioInfo`/`Audio.AudioClip`（`import SLangAudio;` 后裸名/限定均可）；
- 跨模块静态方法可用形态（doc/10 §6 坑⑦修正）：**无参 / string 参数 / string 返回**可靠；非 string 参数（Int32/Float32_3/Array 等）一律 mangle 成 `Core.Object` 不可用——用实例方法或 string 参数重载（如 `Audio.AudioIO.probeFile(string)`）。

原生库：本模块无（纯 SL）。引用 SLangRender/SLangAudio 后其 `sl_render_lib.dll`/`sl_audio_lib.dll` 按各自 package 目录预载（RenderTest 同款机制）。

### 1.4 维护侧提醒（新增文件时）

新 `.sl` 必须登记到模块配置的 `compileFiles`，且**依赖方在后、被依赖方在前**（如 FFI 声明先于使用者）；`spm` 装包会校验 version 与 zip md5，版本与 references 声明不一致会强制重装。这些是构建约束，不是游戏逻辑约束。

## 2. 最小可运行示例（Render 现有 API）

不依赖任何设计稿接口，可在 RenderTest 同款工程中运行：

```sl
import Math;
import SLangRender;

Int32 w = 256
Int32 h = 256
Int64 pixels = Memory.alloc( w * h * 4 )

if !SLang.Render.initialize()
{
    Console.println( SLang.Render.errorString() )
    ret
}

SLang.RenderPipeline pipe = SLang.RenderPipeline.create( w, h )

# 两个对象：一个不透明动画三角，一个透明 quad
SLang.RenderObject tri = pipe.addObject( pipe.MESH_TRIANGLE )
tri.setAnimated( pipe.ANIM_HUE_CYCLE, 0.05f )

SLang.RenderObject quad = pipe.addObject( pipe.MESH_QUAD )
quad.layer = 1                              # queue >= 2500 走透明段

pipe.setCamera( 0x00000003, -1.0f, 1.0f, -1.0f, 1.0f )
pipe.renderFrame( 0.0f, pixels )            # 或 runStages( t, pixels ) 逐阶段

Console.println( "draw calls: " + pipe.stat( pipe.STAT_DRAW_CALLS ).toString() )

tri.destroy()
quad.destroy()
pipe.destroy()
Memory.free( pixels )
SLang.Render.uninitialize()
```

QT 上屏版本见 `09-运行时与帧循环.md` §3、§6；贴图加载见 `../Render/doc/13-Usage-Guide.md`。

## 3. 面向引擎的完整示例【设计稿】

展示本篇设计的目标用法；`GameObject` / `addComponent` / `Application` 尚未落盘，勿直接编译：

```sl
import Std;
import Math;
import SLangRender;

public class Rotator extends Behaviour
{
    public Float32 speed = 45.0f

    override void update()
    {
        this.owner.transform.rotateZ( this.speed * Time.deltaTime )
    }
}

public static void buildScene()
{
    Scene scene = Scene( "Demo" )

    # 共享资源：同 Mesh + 同 Material → 同批次
    Mesh cubeMesh = Mesh.cube( 1.0f )
    Shader shader = Shader( "SlPhong" )
    shader.compile()
    Material sharedMat = Material()
    sharedMat.setShader( shader )

    for int i = 0; i < 10; i++
    {
        GameObject go = scene.createObject( "Cube" + i.toString() )
        go.layer = 0
        go.addComponent<MeshRef>().mesh = cubeMesh
        go.addComponent<MaterialRef>().material = sharedMat
        go.addComponent<Rotator>()                 # 每帧更新 → 建议走单对象批次
    }

    GameObject camGo = scene.createObject( "Main Camera" )
    camGo.addComponent<Camera>()                   # 跟随节点 Transform

    GameObject sunGo = scene.createObject( "Sun" )
    sunGo.addComponent<Light>()                    # directional

    Application.activeScene = scene
}

public static void main()
{
    Application app = Application()
    if !app.init()
    {
        ret
    }
    buildScene()

    # 由 QT QTimer(16) 或主循环调用：app.tick( 0.016f )
    # 退出时：app.shutdown()
}
```

注意示例里 `Rotator` 让每个对象每帧改变变换：按第 05 章 §3.1 的权衡，这些对象建议走单对象批次，静态对象才参与合并。

#### 4.1.1 C99 原生库（sl_sim_engine_lib：时间周期 + 节点管理）

引擎底层时间与节点注册由 C99 库 `sl_sim_engine_lib.dll` 提供（`cvm_sim_engine_lib/`，纯 C ABI 无外部依赖），SL 侧经 `EngineFfi` 单点绑定，封装为 `EngineClock` / `Timer` / `NodeRegistry`。

用例（帧计时）：

```
Int64 frameStart = EngineClock.nowUs()
... 逻辑 ...
Int64 logicUs = EngineClock.nowUs() - frameStart
```

用例（查询式定时器）：

```
Timer t = Timer.create()
t.start()
... ...
Int64 ms = t.elapsedMs()
t.destroy()
```

用例（节点注册表——一般不直用，`Scene.createObject`/`GameObject.destroy` 已自动接线）：

```
Int64 id = NodeRegistry.registerNode( "Boss", "enemy", 3 )
GameObject go = scene.find( "Boss" )      # 裸名单段走 C 哈希 O(1)
NodeRegistry.unregister( id )
```

规则与坑：

- 绑定失效征兆：`EngineClock.nowUs()` 恒 0、`NodeRegistry.count()` 恒 0（走 SL 兜底体）。确认运行目录可达 `sl_sim_engine_lib.dll`（随模块导出/测试包自动拷贝）。
- 节点 id 为句柄语义（1 起始，0 无效）：注销后槽位复用，**不要持久持有 id 跨注销比较**；名字在注册表内全局唯一（跨场景同名时后注册者不入表，`Scene.find` 自动回退树内查找）。
- `Timer.elapsedMs()` 未启动/已销毁返回 -1；busy 等待循环务必带上限（绑定兜底时 nowUs 恒 0 会死循环）。
- 自定义 C 库绑定（照此模式）：C 符号必须显式导出（MSVC 加 `__declspec(dllexport)`，照 `sle_engine.h` 的 `SLE_API`）；jsonc 声明 `dllImports`（`static` 字段填库名触发预载）+ `vmDlls`（构建并拷贝 dll）。
- ⚠ `Memory.readUtf8(addr, offset)` 的语义是「读 addr+offset 处 8 字节地址槽里的 char\*」——对内联 C 字符串缓冲直接传指针会解一层错指针崩溃；读内联字符串要么 FFI 直接声明 `->utf8` 返回（引擎 `sle_node_name_ref` 形态），要么 `readU8` 逐字节拼。

验证：统一入口 `test/Test.sl`（单工程单进程，`Test.runSuite` 常量选套 0=全部/1..6=单套，或注释 `runAll` 分支）——`SimFfiTest` 24 项 + 五套回归，共 156 项全绿；套件源码在 `test/suites/`，产物 `test/export/Test/`。
