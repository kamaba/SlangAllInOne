## 1. 工程接入

### 1.1 依赖组合（RenderTest 已验证）

工程 `.jsonc` 的 `references` 段：

| 模块 | 版本 | 用途 |
|---|---|---|
| `SLangQT` | 0.1.0 | 窗口 / 计时器 / 上屏（无窗口程序可省） |
| `SLangRender` | 1.0.0 | 渲染门面 + 原生库 + RectTransform |
| `Core` / `Std` / `Math` | 随官方库 | `Component` 来自 Std 根级；向量 / 矩阵来自 Math |

可选：`SLangImage 1.0.0`（贴图加载，需 `import SLangImage;`）。

### 1.2 源码 import

```sl
import Std;             # Component / Behaviour 基类
import Math;            # Float32_2/3/4x4、Vector、Mathf
import SLangRender;     # Render / RenderPipeline / Mesh / Material / Shader / Camera / Light / RectTransform
import SLangQT;         # 仅窗口 / 上屏需要
```

### 1.3 目录与产物

```
SLangCore/Lib/SLang/SimGameEngine/
├─ SimGameEngine.sp     # 工程入口（库模块，空 main）
├─ SimGameEngine.jsonc  # 模块配置 / references / systemCalls / export
├─ *.sl                 # 9 个源码文件（编译清单见 jsonc compileFiles）
└─ doc/                 # 本套文档
```

产物按全仓规则写入 `SlangAllInOne/out/export/SimGameEngine/`（`slang compile <模块>.sp --format binary` 落盘；裸路径运行只出内存包）。**消费方必须引用导出的 `SimGameEngine.module.slb`**：路径引用源码 jsonc 只注册类型名、不带成员元数据（成员解析全部失败）。引用链不透传：消费方还需显式引用 Core/Std/Math（不可 `import Core`，只引用）。

原生库：本模块无（纯 SL）。`sl_render_lib.dll` 的要求仅在使用 SLangRender 时适用。

### 1.4 维护侧提醒（新增文件时）

新 `.sl` 必须登记到模块配置的 `compileFiles`，且**依赖方在后、被依赖方在前**（如 FFI 声明先于使用者）；`spm` 装包会校验 version 与 zip md5，版本与 references 声明不一致会强制重装。这些是构建约束，不是游戏逻辑约束。

## 2. 最小可运行示例（Render 现有 API）

不依赖任何设计稿接口，可在 RenderTest 同款工程中运行：

```sl
import Math;
import SLangRender;

Int32 w = 256
Int32 h = 256
Int64 pixels = Memory.alloc( w * h * 4 )

if !SLang.Render.initialize()
{
    Console.println( SLang.Render.errorString() )
    ret
}

SLang.RenderPipeline pipe = SLang.RenderPipeline.create( w, h )

# 两个对象：一个不透明动画三角，一个透明 quad
SLang.RenderObject tri = pipe.addObject( pipe.MESH_TRIANGLE )
tri.setAnimated( pipe.ANIM_HUE_CYCLE, 0.05f )

SLang.RenderObject quad = pipe.addObject( pipe.MESH_QUAD )
quad.layer = 1                              # queue >= 2500 走透明段

pipe.setCamera( 0x00000003, -1.0f, 1.0f, -1.0f, 1.0f )
pipe.renderFrame( 0.0f, pixels )            # 或 runStages( t, pixels ) 逐阶段

Console.println( "draw calls: " + pipe.stat( pipe.STAT_DRAW_CALLS ).toString() )

tri.destroy()
quad.destroy()
pipe.destroy()
Memory.free( pixels )
SLang.Render.uninitialize()
```

QT 上屏版本见 `09-运行时与帧循环.md` §3、§6；贴图加载见 `../Render/doc/13-Usage-Guide.md`。

## 3. 面向引擎的完整示例【设计稿】

展示本篇设计的目标用法；`GameObject` / `addComponent` / `Application` 尚未落盘，勿直接编译：

```sl
import Std;
import Math;
import SLangRender;

public class Rotator extends Behaviour
{
    public Float32 speed = 45.0f

    override void update()
    {
        this.owner.transform.rotateZ( this.speed * Time.deltaTime )
    }
}

public static void buildScene()
{
    Scene scene = Scene( "Demo" )

    # 共享资源：同 Mesh + 同 Material → 同批次
    Mesh cubeMesh = Mesh.cube( 1.0f )
    Shader shader = Shader( "SlPhong" )
    shader.compile()
    Material sharedMat = Material()
    sharedMat.setShader( shader )

    for int i = 0; i < 10; i++
    {
        GameObject go = scene.createObject( "Cube" + i.toString() )
        go.layer = 0
        go.addComponent<MeshRef>().mesh = cubeMesh
        go.addComponent<MaterialRef>().material = sharedMat
        go.addComponent<Rotator>()                 # 每帧更新 → 建议走单对象批次
    }

    GameObject camGo = scene.createObject( "Main Camera" )
    camGo.addComponent<Camera>()                   # 跟随节点 Transform

    GameObject sunGo = scene.createObject( "Sun" )
    sunGo.addComponent<Light>()                    # directional

    Application.activeScene = scene
}

public static void main()
{
    Application app = Application()
    if !app.init()
    {
        ret
    }
    buildScene()

    # 由 QT QTimer(16) 或主循环调用：app.tick( 0.016f )
    # 退出时：app.shutdown()
}
```

注意示例里 `Rotator` 让每个对象每帧改变变换：按第 05 章 §3.1 的权衡，这些对象建议走单对象批次，静态对象才参与合并。

## 5. 差距与路线

| 阶段 | 内容 | 依赖 | 验收标准 |
|---|---|---|---|
| P0（先落） | `.sp` / `.jsonc` 工程；`GameObject` + `Transform` + `Scene` + 组件容器 | Std `Component`、references 建立 | 能创建父子节点、激活传播正确。**✅ 2026-11-16**：模块可编译/导出/运行；`SimEngineTest` 60 项全绿（树/变换/组件去重/生命周期/激活传播/延迟销毁/查找） |
| P1 | 帧循环 `Application` + 可见性收集 + 合批器 | P0 + Render `addObject/uploadMesh` | 手写提交与引擎提交出图一致；`stat` 显示 draw call 下降。**✅ 2026-11-16（无头子集）**：`Application.tick` 落盘（fixedUpdate 累加器 / paused / timeScale / 变换刷新 / 帧尾销毁收口）；可见性收集与合批随 P2 |
| P2 | `MeshRef` / `MaterialRef` 组件 + 第 05 章合批键完整实现 | P1 | 共享材质对象合批、不同材质拆批。**✅ 2026-11-16（数据层）**：`MaterialData`/`MeshRef`/`MaterialRef`/`BatchGroup`/`Batcher` 落盘，`SimBatchTest` 28 项全绿（共享材质合批 / 材质·queue·layer·实例色拆批 / 256 上限 / 单对象直通 / 烘焙含旋转缩放）；Submit 段（驱动 SLangRender）随双模块同名专项 |
| P3 | 碰撞检测：`Collider` / 宽相窄相 / 碰撞矩阵 / 触发器事件（第 11 章） | P0 + 已落盘 Bounds/Plane/Ray | 重叠判定正确；Enter/Stay/Exit 不漏发 |
| P4 | 轻量物理：`Rigidbody` + 固定步长积分 + 冲量求解（第 12 章） | P3 + 第 09 章固定步长 | 小球落地稳定；不同帧率结果一致 |
| P5 | Animation / Effect / UI 事件分发 / Probe 数据结构 | P2 | 动画不拆错批；UI 命中优先级正确 |
| P6 | 天空盒（第 13 章）+ Volume 参数栈（第 14 章） | Render 修 Skybox shader bug / 完成 P2 与 M5 | 天空盒随相机；Volume 混合参数生效 |
| P7 | 2D 渲染：SpriteRenderer / 排序层 / Tilemap（第 15 章） | P2 + P5，图集由业务侧提供 | 精灵按层排序；贴图相同的精灵合批 |
| P8 | Unity 资源管线：Editor 导出器（第 16 章）+ 引擎 `SceneImporter` | P2 + P5，Unity 侧 UPM 包 Editor asmdef 已就绪 | 导出→导入后节点数/顶点数/贴图数与 Unity 一致。**✅ 2026-11-16 首通**：导出器已落盘（`export-scene`/`export-cube`），SimSceneTest 端到端 PASS（Unity Cube → SLangRender 渲染 937 帧）；剩余：完整 SceneImporter 随 P0-P2 组件落地后接入 |
| P9（远期） | 场景序列化 / 热重载 / 编辑器集成 | P8 | 场景存盘再载入画面一致 |

依赖待建项优先级最高：`UIBehaviour` → `RectTransform` 的类型解析（第 08 章 §3.1）。

## 6. 坑汇总（跨章索引）

| 坑 | 处理 | 章节 |
|---|---|---|
| **引用链不透传** | 消费方引用 `SimGameEngine.module.slb`（路径引用源码 jsonc 只有类型名无成员）+ 显式引用 Core/Std/Math（不可 `import Core`，只引用） | 10 |
| **跨模块 slb 基类 CallVirt 虚分发失效**（VM 缺陷，已登记未解决问题） | 消费方模块 override 的钩子不被派发（静态落到基类空实现）；引擎内全部钩子经 `SystemSimEngineCallHook` 按名派发；用户代码勿直接调 `behaviour.setEnabled(...)`（跨模块派生实例上不可靠），用 `SystemSimEngineSetEnabled/GetEnabled` 或节点级 API | 02 / 09 / 10 |
| **方法级泛型构造 `T()` 编译器崩溃**（ParseStatements 空引用，MetaCallLink.AddVisitNodeList，已登记） | `addComponent<T>()` 形态不可用；用「调用方构造 + 引擎去重挂载」：`go.addComponent( Probe() )` | 02 / 10 |
| **跨模块「成员.方法」链式调用返回 Object** | `go.transform.worldPosition()` 一类 a.b().c() 链一律拆单步局部变量（SimSceneTest 同坑） | 10 |
| **三连 `&&` 链报「布尔参与加减运算」** | `&&` 只写双操作数；复杂条件拆 bool 局部变量 | 10 |
| **`List.remove` 对跨模块基类派生对象不可靠**（C 侧 compare_equal 走同一断点；indexOf/SL 层 `==` 正常） | 引擎摘除一律 `indexOf` + `removeAt`；业务侧同 | 02 / 10 |
| **List 表达式下标 `list[i-1]` 解析失败**（not array and no _getItem_） | 下标先落局部变量再访问；`Array<T>` 不受此限 | 10 |
| **List 下标写（`_setItem_` override）跨模块静默失效** | 交换/排序用 `insert`/`removeAt` 普通方法（Batcher 稳定插入排序同款） | 10 |
| **方法返回值形态的 List 容器跨模块读坏**（`roots().length` 空值） | 用 `rootCount/getRoot`、`groupAt(i)`、`bakeVerticesInto(out)` 单对象/写入式 API | 10 |
| **递归方法内跨模块字段读失效**（同代码非递归可靠） | 树遍历用显式栈（Batcher.collect 同款），不用递归 | 10 |
| **Behaviour 子类实例 Int32 字段读返回垃圾且 `== 常量` 失效** | 「跟随/覆盖」判定用 `< 1` 形态；键值在收集上下文一次读入平行数组；材质身份用引用比较 | 10 |
| **`_init_` 内静态字段自增破坏后续字段读** | 身份/计数分配放静态工厂（`MaterialData.create` 同款），不放构造器 | 10 |
| **跨模块静态方法 IR 签名错位**（`Xxx.create_1_Core.Object not found`） | 消费方用构造器 + 实例方法；模块内静态互调不受影响 | 10 |
| **循环条件 `>=` 不生效** | 用 `> 0 - 1` 等价替换 | 10 |
| **双模块根级同名类**（引擎 `Transform`/`Ray` ↔ Render 同名） | `UIBehaviour`（需 RectTransform）暂不入编译集；接线随 P5 专项（迁回本模块或改名） | 08 / 10 |
| `local` / `next` / `half` 是保留字 | 变量命名避让（`localMatrix` 方法名可用，局部变量 `local`/`next` 不可） | 10 |
| Core.String 无 `split/indexOf`；表达式不可跨行续写 | 引擎用 `Scene.splitPath`（slice 扫描）；长 `&&`/`||` 写单行 | 10 |
| `Renderer.render()` 恒 false | 一切绘制走合批器 → RenderObject | 04 / 05 |
| 后端切换作废旧句柄 | `shutdown()` 后全量重建场景与资源 | 01 / 04 / 05 / 09 |
| layer 与 cullMask 不一致 | 位掩码 `1<<N` 严格对齐 | 03 / 06 |
| `setRotationZ` 仅 Z 轴 | 复杂旋转烘焙进合并顶点 | 05 |
| 动画相位是批次级参数 | 不同 mode/speed 拆批 | 05 / 07 |
| 透明对象不合批 | queue ≥2500 独立排序提交 | 05 |
| `rectTransform` 为 null 时 UI 静默失效 | 创建 UI 组件后立即赋值 | 08 |
| `RectTransform` 跨模块定义 | 建 `import SLangRender` / `references`，或迁回本模块 | 08 |
| `Behaviour.setEnabled` 同值不触发钩子 | 需要刷新状态时显式改值 | 02 |
| 射线未命中返回 -1 而非 0 | 判 `>= 0` | 03 |
| 延迟销毁后同帧仍可读到节点 | 需立刻不可见先 `setActive(false)` | 02 / 09 |
| 贴图需 `SLangImage` | `references` + `import SLangImage;` | 01 / 04 / 13 / 15 |
| 旋转节点的 AABB 失真 | 变换后顶点重新 `Bounds.fromPoints()` | 03 / 11 |
| 物理不能用 `update()` 驱动 | 只进 `fixedUpdate` 累加器 | 09 / 12 |
| 触发器不提供接触法线 | 需要反弹就改为非 trigger | 11 |
| Skybox shader 的非法 `#include Common` | 等 Render 修复；勿直接编译 HlslLibrary 源码 | 13 |
| Volume 参数栈未开始 | 现阶段只调 Render 的 4 个后处理参数 | 14 |
| 2D 精灵与 UI 混层 | 独立 layer + cullMask 隔离 | 08 / 15 |
| 透明精灵 queue 不对 | `queue >= 2500` 才进透明段 | 05 / 15 |
