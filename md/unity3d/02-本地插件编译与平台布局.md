# 02 · 本地插件编译与平台布局

> 把 **C VM（`csimple_lang`，C99，可当 C++ 编译）** 编译为 **Unity 原生插件（C++ 库）**，
> 并复用既有平台目录约定 `lib\{windows,linux,macos,ios,android}`
> （`csimple_lang/md/design/PLUGIN_SYSTEM_DESIGN.md`）。

---

## 1. 为什么用 C++ 原生插件（而不是托管 DLL）

Unity 原生插件（Native Plugin）是 C/C++ 编译的库，经 C ABI 暴露 `extern "C"` 符号，
由 C# 侧 `DllImport` / IL2CPP `extern` 调用。选择它因为：

1. **C VM 本身就是 C99**，无托管依赖，天然适合编成原生插件（对标 `csimple_lang_dll.dll`）。
2. **独立于 Unity 后端**：无论 Unity 用 Mono 还是 IL2CPP，原生插件都是同一份机器码，行为一致。
3. **可上 iOS/WebGL**：原生插件能以静态库（iOS `.a`）/ wasm（WebGL）形态存在；托管 DLL 在 iOS AOT 受限。
4. **与既有产物同构**：`csimple_lang_dll` 已是 P/Invoke dll（`csimple_lang/md/cli.md` 宿主 API 段），Unity 侧直接复用其导出符号。

---

## 2. 平台目录对齐（核心）

Unity 原生插件按平台分目录，与 C VM 既有 `sl_platform_dir_name()` 约定**完全一致**：

| 平台 | Unity 原生插件布局 | C VM / 插件既有约定 |
|------|-------------------|---------------------|
| Windows x64 | `Plugins/x86_64/csimple_lang.dll` | `lib\windows\` |
| macOS | `Plugins/macOS/libcsimple_lang.bundle` 或 `.dylib` | `lib\macos\` |
| Linux | `Plugins/x86_64/libcsimple_lang.so` | `lib\linux\` |
| iOS | 静态库 `libcsimple_lang.a` + 源（Unity 编进 Xcode） | `lib\ios\` |
| Android | `Plugins/Android/libs/<abi>/libcsimple_lang.so` | `lib\android\` |
| WebGL | `Plugins/WebGL/csimple_lang.wasm` + js | wasm 通道 |

> 可直接复用 `PLUGIN_SYSTEM_DESIGN.md` 的 `package\{windows,linux,macos,ios,android}` 打包惯例：
> 把 C VM 产物按平台目录导出，Unity 侧用 `.meta` 的 `PlatformSettings` 把每个文件绑定到对应平台。

---

## 3. 编译要点（C99 → Unity 原生插件）

### 3.1 通用
- **ANSI C99 / C++ 兼容**：C VM 源码已满足 R4（C99、零警告 `-Wall -Wextra -Wpedantic`）。Unity 用 C++ 编译器（MSVC / clang）编原生插件时，确保 `.c` 以 C 方式编译（或整体按 C++ 编，需确认无 C++ 关键字冲突）。
- **平台代码隔离（R3）**：C VM 的 `src/vm/**` 禁平台代码；平台逻辑在 `src/lib/{os,time,thread,windows}/`。Unity 插件**不引入 Unity 头文件进 VM 核心**，Unity 交互全部走宿主桥接层（`03`）。
- **DLLEXPORT 宏**：`csimple_lang_dll` 已有导出宏，Unity 侧 `DllImport("csimple_lang")` 链接同名符号（`cli_main` / `cli_run_module_in_memory`）。

### 3.2 Windows（MSVC）
- 复用 `csimple_lang` 现有 `project/vs/vm_lib` vcxproj，产出 `csimple_lang_dll.dll`。
- **R6 登记**：新增的 `.c` 必须同时登记根 `CMakeLists.txt` 的 `CSIMPLE_LIB_SOURCES` 与 `project/vs/vm_lib/csimple_lang_lib.vcxproj`（含 `.filters`）。
- 关联 DLL 预装载：参照 `csimple_lang/md/cli.md` 应用载荷模式的 `sl_preload_associated_dlls()`（`sqlite3.dll` 等 FFI 依赖按 `lib\<平台>\` 解析）。

### 3.3 macOS / iOS
- macOS：编 `.dylib` 或 `.bundle`；注意 Unity 对 macOS 插件要求 **通用二进制 / 指定架构**。
- iOS：**必须静态库 `.a`**（iOS 不允许动态库注入）。JIT 能力 `VM_JIT_ENABLE` 在 iOS 构建**强制 OFF**（`JIT_DESIGN.md` §6.1：非 x86-64 / AOT 默认 OFF）。
- iOS 还需把 C VM 源加入 Unity 生成的 Xcode 工程（Unity 原生插件支持「源文件 + 静态库」混合）。

### 3.4 Android
- 用 NDK 编 `libcsimple_lang.so`，按 ABI（`arm64-v8a` / `armeabi-v7a` / `x86_64`）分目录。
- JIT：`arm64` 后端在 `JIT_DESIGN.md` 列为 P5，当前默认 OFF → Android 实际走解释执行，与 iOS 一致。

### 3.5 WebGL
- 复用 `csimple_lang/md/WASM_BUILD.md` 的 `scripts/cmake-build-wasm.ps1` 独立树；产物 `.wasm` + 胶水 js，Unity WebGL 模板放置。

---

## 4. 与 C VM 主线构建的关系

- Unity 插件构建**不是新建一套 VM**，而是**复用同一份 `src/`**，仅换构建目标（原生插件形态）+ 平台宏。
- 建议：在 `csimple_lang/CMakeLists.txt` 增加 `unity_plugin` 预设（或独立 toolchain 文件），不破坏现有 `vm_lib` / `vm_exe` 链。
- **版本目录**（`SLVM_VERSION_DIR`，R17）：Unity 插件产物也按 `0.0.59` 版本目录落盘，与四端版本统一。

---

## 5. 插件 .meta 设置（Unity 侧）

| 设置项 | 值 | 说明 |
|--------|----|------|
| `Is Preloaded` | false | 按需 `DllImport` 加载 |
| `Platform` | 按平台勾选 | Windows / macOS / Linux / iOS / Android / WebGL |
| `CPU` | x86_64 / arm64 | 与导出 ABI 一致 |
| `OS` | 对应系统 | |
| iOS `Add to Embedded Binaries` | 视 Unity 版本 | 静态库通常不需要 |

## 6. 验收清单（本步交付判据）

- [ ] Windows：`csimple_lang.dll` 能被 Unity C# `DllImport` 成功加载并调 `cli_version` 类接口返回 `0.0.59`。
- [ ] iOS：`.a` 被编入 Xcode 工程，Archive 通过（无 JIT 符号）。
- [ ] Android：`libcsimple_lang.so` 在 `arm64-v8a` 下 `System.loadLibrary` 等价成功。
- [ ] R6 登记无遗漏（任一平台构建不含缺失 .c）。
- [ ] `SL_JIT=0` 在该构建下运行解释执行正常（`08` 联动）。
