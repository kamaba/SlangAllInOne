## 2. 分阶段落地计划（类比 MONO 四阶段）

### 阶段 1 · 跑通原生插件装载（对应 `02`/`03`）
- 把 `csimple_lang_dll` 当 Unity 原生插件编出 Win x64 dll。
- Unity C# `DllImport` 调 `cli_run_module_in_memory` 跑通一个**无绑定**的纯 SL 模块（打印到 `Debug.Log`）。
- 判据：Editor + Standalone 都能加载运行。

### 阶段 2 · 接通绑定与生命周期（对应 `05`/`06`）
- 实现 `SystemUnity.Log` / `GetTransform` / `Find` 等最小 systemCall（R7 四处同步）。
- `SlangLifecycle` 接 `Awake/Start/Update`，host 回调把 Unity 对象经 handle 表暴露给 SL。
- 判据：HelloCube 旋转 + 日志（见 `12`）。

### 阶段 3 · 热更闭环 + 多平台（对应 `04`/`08`/`09`/`10`）
- 文件监视触发重编译/重装载（`04`）；统一关 JIT（`08`）。
- 编译管线集成（`09`）；iOS/Android/WebGL 部署（`10`）。
- 判据：六平台构建 + 真机热更成功。

### 阶段 4 · 调试 / 安全 / 进阶（对应 `07`/`11`/`05`§2.3）
- SLDP 调试器 Editor 扩展（`07`）。
- 签名校验 + systemCall 白名单（`11`）。
- 类 `UnityBehaviour` 代理对象桥、`MonoBehaviour` 式体验（`05` §2.3）。
- 跨热更状态保留（`04` §4.2）。

## 4. 风险与注意事项

1. **线程**：Unity 原生线程不能回调 C# → VM 调用限主线程（`03` §3、`06` §2、`06` §6）。
2. **Domain Reload**：Editor 重载域须重建桥接句柄（`06` §3）。
3. **GC 跨边界**：handle 表必须随 isolate 退出清理（`05` §6）。
4. **JIT 硬约束**：IL2CPP/iOS/WebGL 一律关（`08`），漏关即崩。
5. **ABI 纪律**：host 表 / `SLVmExtVm` 新增字段只追加尾部（`JIT_DESIGN` F9）。
6. **版本**：四端 + Unity 插件版本同步 +1（R17）。
