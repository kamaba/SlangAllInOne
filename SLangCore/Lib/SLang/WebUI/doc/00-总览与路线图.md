# SLang × WebUI 集成 —— 总览与路线图

> 本文是 `SLangCore/Lib/SLang/WebUI/` 模块的设计总纲，描述「把开源 GUI 库
> [webui-dev/webui](https://github.com/webui-dev/webui) 接入 SLang，让 SLang 程序能用
> 系统浏览器作 GUI」的整体方案。配套设计文档见本文末尾「文档索引」。
>
> 落点目录：`SlangAllInOne/SLangCore/Lib/SLang/WebUI/`
> - `WebUI.sp` / `WebUI.jsonc` —— 模块工程入口与配置（实现期产出）
> - `WebUI.sl` —— SL 层封装（实现期产出）
> - `cvm_webui_lib/` —— 原生 C 包装库（实现期产出，内嵌 webui.c）
> - `doc/` —— 本设计文档集

## 1. 背景与目标

SLang 当前已有三类「界面 / 呈现」相关能力：

| 模块 | 形态 | 适用 |
|---|---|---|
| `SLang.Server` | HTTP / WebSocket 服务框架 | 后端服务，需另起浏览器访问 |
| `SLang.Render` | Canvas / 图形渲染 | 图形绘制（非桌面窗口） |
| `SLang.QT` | Qt 工具包绑定 | 重型桌面 UI（依赖 Qt 运行时） |

**缺失的一环**：用「最小的本地程序 + 系统已装浏览器」直接做出桌面 GUI 应用。
这正是 [webui](https://webui.me) 的专长——它**不内嵌 WebView 运行时**，而是启动
用户系统里任意已装浏览器（Chrome / Edge / Firefox …）作为 GUI，后端用你偏好的语言
驱动，前端用 HTML/CSS/JS。程序体积小、启动快、可移植。

**目标**：让 SLang 程序能这样写桌面 GUI：

```sl
import SLangWebUI;

SLang.WebUI.Window win = new SLang.WebUI.Window()
win.bindHandle( "myClick", function( Int64 e ){
    string name = SLang.WebUI.getArgString( e, 0 )
    SLang.WebUI.returnString( e, "Hello, " + name + "!" )
} )
win.show( "<button id='b' onclick=\"myClick('world')\">Click</button>" )
SLang.WebUI.wait()          // 阻塞直到所有窗口关闭
```

## 2. 核心结论（先给答案）

- **接入形态**：复用 SLang 已有的 **FFI 静态绑定**链路（`@DllStaticImport` →
  `CallFFIStatic(77)`），与 `SLang.Mysql`（`sl_mysql_lib.dll`）完全一致的模式。
- **原生包装库**：新建 `cvm_webui_lib`（产出 `webui_lib.dll`），把 webui 的
  `webui_event_t` 等不透明结构**扁平化为 SL 可直接搬运的标量**（窗口号 = `size_t`→`Int64`、
  事件指针 = `ptr`、字符串 = `utf8`），并内置**回调函数指针分发表**（见 02/04）。
- **回调机制**：webui 的 `void (*)(webui_event_t*)` 回调 → 经原生层 trampoline →
  调 SLang 的 `FFI.StaticLibrary.createCallback` 生成的回调节流点**重入 VM**，SL 处理函数
  签名 `static void onEvent(Int64 eventPtr)`。两层回调，零额外胶水。
- **许可**：webui 是 **MIT**（vs Mysql 的 GPL-2.0），可**随官方发布包分发**，无红线。
- **线程安全是第一风险**：webui 默认每个事件在独立线程处理；SLang VM 重入需先序列化
  （默认 `webui_set_event_blocking(window, true)`），详见 02 §4 与 07。

## 3. 参考范式（照抄 Mysql 集成）

`SLang.Mysql` 是本题的**权威模板**，结构一一对应：

| 层 | Mysql（已有） | WebUI（本方案） |
|---|---|---|
| SL 封装 | `MysqlClient.sl`（`@DllStaticImport` 直调 `slm_*`） | `WebUI.sl`（直调 `webui_*`） |
| 工程配置 | `MysqlClient.jsonc`（`dllImports`+`vmDlls`+`references`+`struct`） | `WebUI.jsonc`（同构） |
| 原生库 | `cvm_sl_mysql_lib/`（内嵌 mysqlclient.lib，静态链接） | `cvm_webui_lib/`（内嵌 webui.c，静态编译） |
| 模块名 | `SLangMysql` | `SLangWebUI` |
| 文档 | `MysqlClient.md` | `doc/` 本设计集 + 实现后补 `WebUI.md` |

## 5. 版本与合规

- 遵循 `AGENTS.md` **R17 四端版本统一**：本模块不引入独立版本号，沿用仓内统一版本
  （当前 `0.0.38`）；模块 `jsonc` 的 `export.versionMain/Sub/Patch` 仅表达模块语义版本，
  不与仓内统一版本号冲突（沿用 Mysql 的 `1.0.0` 风格即可）。
- 遵循 **R14**：任何代码/配置改动必须配套文档；本设计集即为 P0 的文档落点。
- 遵循 **R16**：本目录新建文本文件统一 UTF-8。
- 遵循 **R3**：原生包装库是独立 `cvm_webui_lib`，其内的平台代码来自 vendored webui 本身，
  SLang 核心 `csimple_lang/src/vm/**` 不引入平台代码；webui 的 Win/Linux/mac 差异由
  webui 源码自身 `_WIN32/__linux__/__APPLE__` 分支承担。

## 7. 未决问题（待 P0 评审确认）

1. **模块命名空间**：用 `SLang.WebUI`（平铺在 `SLang` 下，与 Mysql 一致）还是独立
   `WebUI`？本方案默认 `SLang.WebUI`，与 Mysql 同构。
2. **是否内嵌 webui.c 还是动态链接 `webui.dll`**：默认内嵌（自包含、无外部依赖，
   与 mysqlclient 静态链接同思路；MIT 允许）。
3. **默认事件线程模型**：默认 `event_blocking=true`（安全优先），是否提供非阻塞
   多客户端（`multi_client`）模式留待后续（需 VM 线程安全改造）。
