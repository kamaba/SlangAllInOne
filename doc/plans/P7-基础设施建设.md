# P7 · 基础设施建设（CI / Front 重入 / Playground / 文档站）—— 执行计划

> **定位**：不产出新功能，但决定其他所有计划的**安全性与效率**。单项成本极低、收益覆盖全部后续开发，建议 P0 开工当日同步启动。
> **依赖**：无。**节奏**：伴随各阶段穿插执行。

---

## T1 · CI 自动化（GitHub Actions）——最紧急的便宜事

**理由**：单人维护四端 16 工程 + opcode 逐项对齐（R2）这类脆约束，回归测试是生命线。历史教训已多次（版本混体"缝合怪"、jsonc 路径漏迁导致 compile-tests 恒 FAILED 等）。

**步骤**：
1. 仓库根新建 `.github/workflows/ci.yml`，双矩阵触发（push + PR）：

```yaml
jobs:
  windows:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: '8.0.x' }
      # C VM 构建（脚本已自动补装 cmake/ninja）
      - run: powershell -File SlangAllInOne/scripts/build-vm-win.ps1 -Config Release
      # 标准库 + 用例集编译 + 运行 + 退出码汇总
      - run: powershell -File SlangAllInOne/scripts/build-all.ps1 -Run
  linux:
    runs-on: ubuntu-latest          # 免 WSL，脚本走原生 Linux 分支
    steps:
      - uses: actions/checkout@v4
      - run: sudo apt-get install -y clang cmake ninja-build
      - run: powershell -File SlangAllInOne/scripts/build-vm-linux.ps1 -Config Release
      - run: powershell -File SlangAllInOne/scripts/run-tests-linux.ps1
```

2. **失败即红**：任一用例非 0 退出码让 job 失败（脚本已有退出码汇总，直接消费）；
3. 徽章挂 README 顶部；
4. **注意坑**：中文 MSVS `/showIncludes` 与 Ninja deps 的问题（PROJECTS.md §7.5）在 CI 的英文环境不存在，但本地纪律照旧；四端版本锚点一致性加一个轻检查 job（grep 四处版本号相等，不等则红——防止再出现 0.0.24 错位）；
5. 缓存：NuGet 包 + C VM 构建目录缓存（keys 按 csproj/CMakeLists 哈希）。

**验收**：故意改坏一个 opcode 枚举 → CI 红；恢复 → 绿。徽章上线。
**工期**：1 天。

## T2 · Front 进程内重入根治 + 增量编译演进入口

**现状**（AGENTS.md / README 已记录）：LSP 每轮 spawn `slang lsp-compile` 子进程全量编译，规避 Front 同进程二次编译的静态状态残留（`isLoaded` / `fileParseList` / `ProcessManager`）；Front 已留 `ProjectCompile.ResetForNewSession()` 备用口未启用。

**步骤**：
1. **审计静态状态**：grep `simple_language\source\` 全部 `static` 可变字段，归类清单（哪些是缓存可清 / 哪些是配置应保持 / 哪些是脏状态必须清）；
2. **实现 Reset**：启用并补全 `ResetForNewSession()`——目标：同进程连续两次编译工程 A→A / A→B，第二次结果与冷进程一致；
3. **一致性测试**：`CSimpleVMTest` 加"连续编译"模式（同进程连编 3 个工程，产物与单编 diff）；
4. **LSP 切换**：`LspServer.DoDiagnostics` 从 spawn 模式切回进程内调用（保留 spawn 作为回退开关 `--lsp-spawn`）；
5. **增量编译（远期入口，不在本任务实现）**：重入根治后才有条件做"只重编改动文件"——登记为后续独立项。

**验收**：LSP 保存→诊断延迟显著下降（对比 spawn 模式测量）；连编一致性测试全绿。
**工期**：3~4 天。

## T3 · WASM Playground 上官网（几乎零成本）

**现状**：`csimple_lang\wasm\playground.html` 已实现"浏览器写 SL → 服务端 Front 编译 → 浏览器 wasm 执行"（`node wasm\server.js` → localhost:8080/playground）；官网"运行页"设计稿已有（`SLangOfficialWebsite\doc\06-运行页设计.md`）。

**步骤**：
1. Playground 服务端部署到官网服务器（deploy/ 目录 nginx 配置已有可参照）；
2. 官网运行页（Astro）嵌入 iframe 或独立子域 `playground.slang.xxx`；
3. 预置示例下拉（HelloWorld / 斐波那契 / 协程 / List 操作——从 samples/ 精选 8~10 个）；
4. 防滥用：限流（nginx）+ 编译超时杀进程；
5. 官网下载页/首页 CTA "在线试一试 →" 指向运行页。

**验收**：无需注册安装，浏览器 30 秒内跑通第一个 SL 程序。
**工期**：1~2 天。

## T4 · 在线文档站

**现状**：`SlangAllInOne\md\` 93 篇用户文档（syntax 48 篇 + lib + project + log + plugins），无统一在线站；官网 i18n 方案已设计（doc/14）。

**步骤**：
1. 选型：Astro Starlight（与官网同框架，md 直迁）或 VitePress；
2. 结构映射：`md/syntax/ → 语法`、`md/lib/ → 标准库`、`md/project/ → 工程指南`、`md/CLI.md + GUIDE.md → 入门`；
3. 版本化：文档站随 Release tag 快照（v0.0.x）；
4. 导航/搜索（Starlight 内置 pagefind）；
5. md/INDEX.md 与站内导航对齐，双入口维护单一真源（构建脚本从 md/ 生成站，**不复制文件**）。

**验收**：docs.slang.xxx 上线，全 93 篇可检索。
**工期**：2~3 天。

## T5 · 测试广度持续补强（伴随项）

1. **旧用例恢复**：同 P0-T7（`test\Other\` 未迁移用例从 git 历史恢复）——若 P0 未做完此处兜底；
2. **负例测试**：编译期错误用例集（每条 LID 至少一例触发，`resources/errors.csv` 为真源）；
3. **探针用例常态化**：CoroGCProbe / OOMProbe / TLSFProbe 挂进 CI 周任务（每日跑一次即可，防 GC/内存回归）；
4. **用例计数看板**：CI 输出汇总各套件用例数，数量下降即警觉（防用例被静默跳过）。

**工期**：持续，每周投半天。

## 执行顺序

```
T1 CI（立即，1 天）──► T5 测试补强（持续伴随）
T3 Playground 上官网（P1 阶段 F1 合并执行）
T2 Front 重入（P0 完成后插入，P4 之前完成——LSP 体验影响开发效率）
T4 文档站（P1 官网完善阶段合并执行）
```

## 验收标准（总）

- [ ] CI 双平台绿灯徽章上线，版本锚点一致性检查生效；
- [ ] LSP 诊断不再依赖子进程 spawn（进程内直调），延迟可测量下降；
- [ ] 官网在线 Playground + 文档站上线；
- [ ] 旧用例 100% 恢复进套件，负例测试覆盖主要 LID。

## 风险与对策

| 风险 | 对策 |
|------|------|
| CI 时长过长拖慢迭代 | 缓存 + 用例集分级（push 跑核心 / nightly 跑全量） |
| Front 静态状态清理引发新回归 | 一致性测试先行，spawn 回退开关保留一个版本周期 |
| Playground 被滥用 | 限流 + 超时杀 + 无写盘权限的运行账户 |
