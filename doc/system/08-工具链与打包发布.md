## 2. 编译驱动与测试宿主

### 2.1 CompileStdlib（标准库编译驱动）
- 入口：`Project/CompileStdlib/Program.cs`（预设 `core|std|math|all`，缺省 all，launchSettings profile 分流）。
- 流程：每模块起**干净子进程**隔离 Front 静态状态 → `compile -e ir -p <path> -o3 --format binary+json` → 成功后同步 slb 到 `package/{win32,linux}-{debug,release}/lib/`（json 仅 debug，math_lib.dll 仅 win32）。
- all 顺序：Core → Std → Math。

### 2.2 CSimpleVMTest（联合测试宿主，八合一）
- 入口：`Project/CSimpleVMTest/Program.cs`。
- 六大预设：`BaseTest / ExpendTest(缺省) / MathTest / SpecialTest / BenchMark / RenderTest` + 命名用例表（launchSettings profile 分流）。
- 流程：Front 进程内编译用例集 → 拷产物入包 → 发布包 `slang run` 执行（Debug→`package/win32-debug`，Release→`package/win32-release`，标准库取自包 `lib/`）。

> ⚠ 旧八个测试宿主已删除（CoreTest/Test→BaseTest，StdTest/Test2/CSimpleVMTest→ExpendTest，MathTest/SpecialTest/BenchMark/RenderTest 同名）。

## 3. 发布包布局标准（强制执行版）

权威 = `md/project/package-layout.md §七`。标准 = **主包四件套 + 插件包两件套**。

### 3.1 主包四件套
```
<包根>\
├── slang(.exe)        入口 = Front 编译 + C VM 执行
├── spm.exe            包/插件管理（Native AOT 单文件）
├── bin\               C VM 本体（csimple_lang.exe/dll）+ MLIR/LLVM 工具链（llc/mlir-opt/…）
├── lib\               *.module.slb 平铺 + <平台>\ 关联 dll（sqlite3.dll、math_lib.dll）
├── plugin\<id>\       插件包安装位（见 3.2）
└── md\                用户文档
```

### 3.2 插件包两件套
- dev 树：`plugin/<id>/` = `plugin.jsonc` + `package/`（三工程产物汇聚，见 [07-插件系统](07-插件系统.md) §2）。
- 发布包：剥掉 `package/` 层平铺为 `<包根>/plugin/<id>/plugin.jsonc + *.module.slb + <平台>/`。

### 3.3 全链路一致性（装载路径口径）

| 环节 | 路径行为 |
|------|---------|
| Front references 纯名 | 官方库直查 `<exe>/lib/<名>.module.slb`（slb 优先，modules 兜底） |
| Front `@tag` 路由 | 上溯 `plugin/` → frontendNative dll 取 `package/<平台>/`（发布平铺 `<平台>/` 回退） |
| C VM 引用装载 | `<exe>/lib/` → `<exe>/modules/` 直查（slb 优先） |
| C VM 关联 dll 预载 | `<exe>/lib/<平台>/` → 平铺 `lib/` → `../lib/<平台>/` → `../lib/`（sqlite delay-load） |
| C VM FFI/插件库 | 候选链含 `<exe>/lib/<平台>/<basename>`；发布回退 `<pkg>/plugin/<id>/<平台>/<basename>` |
| AOT 工具链 | `<exe>/bin/` 优先，回落 `simple_language/tools/llvm` |

## 4. 构建 / 测试 / 发布脚本

`d:/project/lang/SlangAllInOne/scripts/`：

| 脚本 | 用途 |
|------|------|
| `build-all.ps1` / `build-packages.ps1` | 总构建 / 打包 |
| `build-vm-win.ps1` / `build-vm-linux.ps1` | C VM 双平台构建（CMake） |
| `compile-stdlib.ps1` / `compile-tests.ps1` | 标准库 / 测试用例编译 |
| `run-tests-win.ps1` / `run-tests-linux.ps1` | 测试运行（一键编译+执行） |
| `release-slang.ps1 -Version <X.Y.Z>` | 正式发布（AOT-only 双平台同发，版本锚点同步 + GitHub Release） |
| `release-local.ps1` | 本地发版一条龙：四包 → vsix → 装入本机 Trae CN |
| `common.ps1` | 公共函数（含 TestMap、VM dll 部署） |

**常用命令**（详见 `PROJECTS.md §5`）：

```powershell
# Front 编译（.sl → module.json）
dotnet run --project simple_language/source/SimpleLanguageFront.csproj -- compile -p <.sp> -e ir
# 标准库全编（Core→Std→Math）
dotnet run --project SlangAllInOne/Project/CompileStdlib/SimpleLanguageCompileStdlib.csproj
# 编译即运行（裸工程路径）
dotnet run --project SlangAllInOne/SlangAllInOne.csproj -- SlangAllInOne/SLangCore/test/BaseTest/ProjectTest --no-banner
# 联合测试（指定套件）
dotnet run --project SlangAllInOne/Project/CSimpleVMTest/CSimpleVMTest.csproj -- BaseTest
# C VM 构建 / 发布
powershell -File scripts/build-vm-win.ps1 -Config Release
powershell -File scripts/release-slang.ps1 -Version <x.y.z>
```

## 7. 构建/发布注意事项

1. **产物根唯一**：`out/export/`；库 jsonc `export.outputDir`、PackModules、测试 references 三方同步，改一处必须全改（历史上 60 处 jsonc 漏改导致产物落错目录）。
2. **版本 bump 全量重编**：C VM 改 `cli_version.h` 后须 `--clean-first`（Debug 与 Release 都要），否则增量构建产出「缝合怪」二进制。
3. **jsonc 无 BOM**：PowerShell `Set-Content -Encoding UTF8` 会写 BOM 致 Text.Json 解析失败；用 `[System.IO.File]::WriteAllText(..., UTF8Encoding(false))`。
4. **C 库导出登记**：C 导出函数必须在头文件声明表登记（漏登记 = dll 无符号 = FFI 静默失败）。
