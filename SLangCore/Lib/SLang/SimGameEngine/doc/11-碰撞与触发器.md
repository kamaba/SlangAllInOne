## 1. 职责边界

| 问题 | 归属 |
|---|---|
| 两个物体是否重叠 / 相交？接触点在哪？法线朝哪？ | **本章**：碰撞检测 |
| 重叠后怎么弹开、怎么传递动量、摩擦多少？ | `12-物理引擎.md`：运动响应 |
| 鼠标点到了哪个物体？ | 第 03 章 `Ray` + `Bounds` 拾取（一次性查询，不是持续重叠） |
| UI 按钮点到了吗？ | 第 08 章 UI 命中（屏幕空间，优先级高于世界拾取） |

碰撞体是挂在 GameObject 上的组件，跟 Transform 走；两个碰撞体必须分别属于两个节点（第 02 章同类组件唯一），碰撞关系是「组件对组件」，事件投递给各自宿主节点上的 Behaviour。

## 2. 碰撞体类型【设计稿】

| 组件 | 形状参数 | 窄相算法 |
|---|---|---|
| `BoxCollider` | `Float32_3 center / size` | AABB 重叠（用 `Bounds.fromCenterSize`） |
| `SphereCollider` | `Float32_3 center`、`Float32 radius` | 球心距判定 |
| `CapsuleCollider` | 两端点 + 半径 | 线段最近点 + 距离 |
| `MeshCollider` | Mesh 引用 + 是否凸包 | 凸包 GJK / 三角网格 BVH（远期） |
| `PlaneCollider` | `Plane` 实例 | 平面有符号距离（第 03 章 `distanceToPoint` 已落盘） |

拟定公共基类：

```sl
public class Collider extends Component
{
    public bool   isTrigger = false
    public int    layer = 0             # 默认继承宿主节点 layer，可覆盖
    public Bounds worldBounds           # 由形状 + 世界变换算出，宽相用

    public bool overlaps( Collider other )
    public bool computeContact( Collider other, out ContactInfo info )
}

public class ContactInfo
{
    public Float32_3 point             # 接触点（世界空间）
    public Float32_3 normal            # 法线（从 other 指向自身）
    public Float32   penetration       # 穿透深度，>= 0
}
```

`worldBounds` 是**轴对齐**盒：节点旋转后要用变换后的顶点重新 `Bounds.fromPoints()` 生成世界 AABB，不能直接拿 local `size` 加世界位置（第 03 章 §5 已说明）。

## 3. 宽相与窄相

### 3.1 宽相（Broadphase）

先排除明显不可能相交的对象对，避免 O(n²) 全配对：

1. **AABB 快速判定**：`worldBounds.intersects(other.worldBounds)`（已落盘）为 false 直接跳过；
2. **空间网格**：把世界划分成固定大小格子，碰撞体登记覆盖的格子，只检测同格对象（设计稿）；
3. **动态对象稀疏、静态对象多**时，静态碰撞体可缓存 AABB，只在 Transform 标脏时刷新。

### 3.2 窄相（Narrowphase）

宽相通过后，按形状对计算精确接触：

| 形状对 | 判定依据 |
|---|---|
| Box / Box | AABB 重叠 + 最小穿透轴 |
| Sphere / Sphere | 中心距 ≤ 半径和 |
| Sphere / Box | 球心到 AABB 的 `closestPoint()` + `distanceTo()`（已落盘） |
| Ray / Collider | `Ray.intersectBounds()` / `Plane.raycast()`（已落盘） |
| Mesh / Mesh | 远期，先退化为 AABB |

### 3.3 碰撞矩阵

按 layer 决定「谁和谁检测」，与渲染的 `cullMask` 是**两套独立掩码**：

```sl
# 设计稿：第 i 位为 1 表示该 layer 与 layer i 碰撞
Int32[] collisionMatrix = [ 0x00000001, ... ]
bool canCollide( int layerA, int layerB )
{
    ret ( collisionMatrix[layerA] & ( 1 << layerB ) ) != 0
}
```

常见配置：玩家 ↔ 敌人 / 地形 / 触发器；触发器 ↔ 玩家；UI layer 不参与世界碰撞。

## 4. 触发器与事件

### 4.1 触发器 vs 实体碰撞体

| 类型 | `isTrigger` | 行为 |
|---|---|---|
| 实体碰撞体 | false | 检测重叠并产生 `ContactInfo`，交给第 12 章求解弹开 |
| 触发器 | true | 只报告进入 / 停留 / 离开，**不产生接触法线与穿透深度**，不阻挡移动 |

触发器体积常用 `BoxCollider` + `isTrigger = true`，用来做拾取区、伤害区、检查点。

### 4.2 钩子（与 Behaviour 生命周期同风格）

```sl
public class PlayerZone extends Behaviour
{
    override void onCollisionEnter( Collider other, ContactInfo info )
    {
        Console.println( "hit " + other.owner.name )
    }

    override void onCollisionStay( Collider other, ContactInfo info )
    {
    }

    override void onCollisionExit( Collider other )
    {
    }

    override void onTriggerEnter( Collider other )
    {
        if other.owner.tag == "Pickup"
        {
            other.owner.destroy()
        }
    }

    override void onTriggerStay( Collider other ) { }
    override void onTriggerExit( Collider other ) { }
}
```

### 4.3 事件投递时机

```
fixedUpdate 阶段：
  1. 更新 worldBounds（脏节点）
  2. 宽相配对 → 窄相求 ContactInfo
  3. 与上一帧接触表比对：
       新出现 → Enter
       持续   → Stay
       消失   → Exit
  4. 实体接触送第 12 章求解；触发器只发事件
  5. 缓存在本帧事件表，update 阶段由脚本读取
```

Enter/Stay/Exit 的判定必须在固定步长里做，否则帧率变化会导致事件漏发或重复。

## 5. 示例：拾取区

```sl
import Std;
import Math;

GameObject pickup = GameObject.create( "HealthPack" )
pickup.layer = 3

BoxCollider trigger = pickup.addComponent<BoxCollider>()
trigger.center = Float32_3.zero()
trigger.size = Float32_3( 1.0f, 1.0f, 1.0f )
trigger.isTrigger = true

# 另一节点挂 Player + BoxCollider(isTrigger=false)
# 玩家进入时 PlayerZone.onTriggerEnter 收到事件并按 tag 处理
```

> 注：`GameObject` / `addComponent` / `BoxCollider` 为设计接口；`Float32_3` 来自 `import Math;`，`Behaviour` 基类已落盘。

## 6. 已知坑与注意

1. **别把渲染 layer 掩码当碰撞矩阵用**：`cullMask` 决定「画不画」，碰撞矩阵决定「碰不碰」，两者语义独立，可以不同值。
2. **旋转节点的 AABB 要重算**：`Bounds` 是轴对齐的；物体转 45° 后仍用未旋转的 local 尺寸会漏检或误检。
3. **穿透过深时接触法线不稳定**：最小穿透轴在接近立方体对角时会跳变；第 12 章的 CCD 与位置修正可缓解。
4. **触发器不提供法线**：不要从 `onTriggerEnter` 里读 `ContactInfo.normal` 做反弹；需要反弹就把碰撞体设为非 trigger。
5. **事件横穿固定步长与渲染帧**：`fixedUpdate` 一帧可能跑多次（第 09 章累加器），Stay 事件可能一帧内出现多次；脚本要做幂等处理。
6. **碰撞组件尚未落盘**：当前可用的是 `Bounds` / `Plane` / `Ray` 的几何判定；本文是碰撞系统的目标契约。
