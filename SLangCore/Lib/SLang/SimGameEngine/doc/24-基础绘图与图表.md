# 24 · 基础绘图与 R 风格图表（v2.21）

> 状态：【已落盘】图元委托 SLangRender.BasicDraw（GDI 原生 / RHI 三角化双后端）；
> 第 23 套 `SimDrawingTest` 59 项全绿。
> 使用文档：`md/lib/SimGameEngine/drawing-and-charts.md`（R21 纯用法）。
> 定位：SimGameEngine 自带的「通用 2D 绘图 + 统计图表」能力，与第 23 章 Windows GDI 画布互补——
> GDI 画布依赖 `slr_gdi_*`/Windows，本章 `DrawCanvas` 跨平台、离屏可用。

---

## 1. 为什么在引擎里再做一套画布

| 已有能力 | 边界 |
|---|---|
| `RenderSystem` / `MeshRef` / `Batcher`（doc/04/05） | 面向场景网格与 RenderObject，画一条线要造三角形网格，不适合数据可视化 |
| `GizmoGeometry`（doc/21） | 编辑器辅助图标专用，几何固定，无画布 |
| `GdiCanvas`（doc/23，SLangRender） | 真 GDI 但仅 Windows，需 render CVM 原生层 |
| `StatsPlot`（独立模块） | R 风格统计绘图已落地，但在引擎外，引擎内消费需额外模块依赖 |

本章目标：**SimGameEngine 内部自带**一个轻量的 RGBA8 离屏画布 + 图元 + R 风格图表工厂，
任何引用 `SimGameEngine` 的工程直接可用；无窗口、无原生库依赖，测试/CI/离屏均可跑。

---

## 2. 分层与文件

| 文件 | 职责 |
|---|---|
| `drawing/DrawTypes.sl` | 常量层：线型 / 点符号 / 图例位置 / 绘图类型 / 调色板 / 颜色构造 / 绘图自带三角与 log2 |
| `drawing/DrawCanvas.sl` | RGBA8 画布 + 图元（点/线/虚线/点线/矩形/圆/椭圆/弧/扇形/多边形/文字） + 上屏/纹理输出 |
| `drawing/PlotParams.sl` | R `par()` 图形参数对象：尺寸/边距/颜色/线型线宽/点符号/标题/坐标范围/网格/图例 |
| `drawing/DrawChart.sl` | 统计辅助 + R 基元图表工厂 + 叠加层（abline/legend） |

四文件已登记 `SimGameEngine.jsonc` 的 `compileFiles`（priority 50..53）与 `struct` 导出表。

## 4. 一帧数据流

```
SL 调用 DrawChart.xxx(数据, params)
  → 内部生成 DrawCanvas（BasicDraw 外观层，见下）
  → 图元委托 SLangRender.BasicDraw（BACKEND_GDI Windows 原生 / BACKEND_RHI GPU 三角化）
  → 返回 DrawCanvas
  → 输出通道二选一：
      · QLabel.setPixmapRgba(pixelPtr(), w, h)        （slQT 窗口上屏；惰性回读快照）
      · DrawCanvas.toTexture() → Submit/RenderObject  （引擎内贴图）
```

> 实现说明：DrawCanvas 不再自带软光栅。create() 默认 GDI 后端（像素语义与
> 测试基准对齐），createBackend(w, h, BasicDraw.BACKEND_RHI) 走 GPU 路径；
> 颜色契约 DrawTypes 0x00RRGGBB 在外观层补 alpha 后转发。

## 5. 坐标与布局契约

- 画布像素 RGBA8 **顶行在前**，alpha 恒 255；与 `QLabel.setPixmapRgba` / `RenderTexture.createRgba` 一致。
- 默认画布 720×480，边距 left=56 / right=18 / top=34 / bottom=38；刻度 5 档。
- `frame()` 画完坐标轴后把「绘图区矩形 + 数据坐标范围」写入画布；`abline`/`legend` 据此换算叠加坐标。
- `arc`/`pieSlice` 角度单位为弧度，y 轴向下；饼图自 12 点方向顺时针推进。
- 自动坐标范围 = 数据 min/max ±5%；`par().setXlim/setYlim` 可覆盖。

## 6. 实证坑（本轮踩过并已修）

| 坑 | 现象 | 规避 |
|---|---|---|
| `half` 是词法保留字 | 变量 `half` 触发 `NodeStructParseNameIsKeyword`，文件层编译失败 | 改 `halfW`（累计保留字表再 +1 条实证） |
| `List.add` 返回 void | 链式 `a.add(x).add(y)` 报 `MetaCoreParseCallNodeNotFoundInClass [Core.Void]` | 拆成多行独立语句 |
| `while` 忘记自增 | `boxplot` 的 `g` 未递增 → 死循环、内存涨到 GB | 每组循环末尾 `g = g + 1`；像素类测试要设超时 |
| `as Int32` 与乘除混写优先级异常 | `cx + (r * cos(a)) as Int32` 把 `cos(a)` 先转 Int32 得 0 → 弧线只画 1 像素 | **先算 Float32 局部变量再单独 cast**：`Float32 x = cxF + rF * c; Int32 ix = x as Int32` |
| 跨模块 `Mathf.cos/sin` 在引擎内不可靠 | 引擎侧调用返回 0（测试侧直接调正常） | 绘图自带 `DrawTypes.sin/cos`（9 阶泰勒 + 区间约化），数学层自包含 |
| 长 `ret` 表达式跨行 | 解析失败 | 中间变量逐项累加后 `ret` |

## 8. 与 stats/（原 StatsPlot）的分工

v2.22 起原独立模块 StatsPlot 已合并入引擎 `stats/`（doc/25），两套接口同属 SimGameEngine：
- `drawing/`（本章）：引擎自带的轻量画布与 R 风格图表工厂，面向「在场景/离屏画布上直接画图」，
  带 `par()` 参数对象与 abline/legend 叠加，API 为 `DrawCanvas` / `DrawChart`。
- `stats/`：原 StatsPlot 的数据分析能力（DataFrame / Stats / Plot / PlotCanvas / PlotIo），
  面向「数据整合 → 描述统计 → 多图形输出」，API 仍为 `StatsPlot.*` 前缀。

两者互补、可混用（QT 图库示例同屏展示 16 个视图即由这两套接口共同生成）。
