# 集成架构设计

> 本文定义 SLang 接入 webui 的**整体结构**：三层划分、FFI 静态绑定主链路、回调桥接
> （核心难点）、线程模型。SL 侧 API 见 `03`，原生层细节见 `04`。

---

## 1. 三层结构

```
┌──────────────────────────────────────────────────────────┐
│  SL 层  WebUI.sl  (namespace SLang.WebUI)                  │
│   - Window 类（句柄/属性/bind/show/wait）                  │
│   - 静态工具：getArgX / returnX / runScript / script       │
│   - 处理函数签名 static void onEvent(Int64 eventPtr)       │
└───────────────┬──────────────────────────────────────────┘
                │ @DllStaticImport → CallFFIStatic(77) 直调
                │ （窗口/属性/JS执行/事件参数读取/事件返回 全部直调）
┌───────────────▼──────────────────────────────────────────┐
│  原生层  cvm_webui_lib  (webui_lib.dll)                    │
│   - 内嵌 webui.c（MIT），对外暴露扁平 C ABI：webui_*_sl    │
│   - 回调桥：webui_bind_sl(window, element, Int64 slCbPtr)  │
│       └ trampoline 池 + bind_id → slCbPtr 映射            │
│   - 事件读取/返回 直接转发 webui_get_*/webui_return_*      │
│   - webui_script_sl(...) 封装输出缓冲区为 string           │
└───────────────┬──────────────────────────────────────────┘
                │ webui C ABI（静态编译内嵌）
┌───────────────▼──────────────────────────────────────────┐
│  webui 库 (webui.c / webui.h, v2.5.0-beta.4, MIT)         │
│   本地 WebServer + WebSocket + 浏览器启动/WebView          │
└──────────────────────────────────────────────────────────┘
```

对照 `SLang.Mysql`：`WebUI.sl` ↔ `MysqlClient.sl`，`webui_lib.dll` ↔ `sl_mysql_lib.dll`，
`cvm_webui_lib` ↔ `cvm_sl_mysql_lib`。**差异仅在多出回调桥**（webui 有 C→SL 回调，
mysql 没有）。

## 2. 主链路：FFI 静态绑定（与 Mysql 同构）

`WebUI.jsonc` 的 `dllImports` 用平铺 basename 形态（同 `MysqlClient.jsonc`）：

```jsonc
"dllImports": [
  { "path": "webui_lib.dll", "name": "webui_lib", "alias": "webui_lib", "static": "webui_lib" }
]
```

- cvm 装载 `SLangWebUI` 模块即预载 `webui_lib.dll` 并注册 FFI 静态绑定表。
- `WebUI.sl` 里**所有非回调** API 用 `@DllStaticImport("webui_lib", "webui_xxx_sl")` 直调，
  绑定失败回退 SL 函数体兜底（返回零值 / 空串）。
- 调用点由 cvm 装配期改写为 `CallFFIStatic(77)`，零 SL 帧、无 wrapper 转发开销。
- 回退链：`pkg_dir/webui_lib.dll` → `pkg_dir/<平台>/webui_lib.dll` → `pkg_dir/webui_lib.dll`
  （同 Mysql）。

### 2.1 为什么用静态绑定而非命令式 FFI

- 与 Mysql 一致、调用零开销；
- 库随模块预载、进程级常驻，避免每次 `LoadLibrary`；
- 函数体即兜底，DLL 缺失时 SL 程序仍可用降级逻辑（如返回 "webui unavailable"）。

## 3. 回调桥（核心难点）

### 3.1 问题

webui 的回调是 `void (*func)(webui_event_t* e)`，webui 在内部线程里调用它。SLang 要响应
这个回调，必须让 C 调用**重入 SLang VM**——这正是 SLang FFI 回调（`FFI.StaticLibrary
.createCallback`）的能力：它生成一个 C trampoline，C 侧调用该 trampoline 即重入 VM 执行
指定 SL 静态方法。

但 webui 的 `webui_bind` 要求传入**它自己的** `void(*)(webui_event_t*)`，而不是 SLang 的
createCallback trampoline（后者签名是 `void(*)(int64_t)`，且参数含义不同）。因此需要一层
**原生 trampoline** 做「webui 事件 → 调 SLang 回调节流点」的桥接。

### 3.2 桥接流程

```
[SL] cbPtr = FFI.StaticLibrary.createCallback( "MyClass.onClick", "ptr->void" )
       → 返回 SLang 回调节流点地址（C 函数指针，签名 void(*)(int64_t)）
[SL] WebUI.bindEvent( win, "onClick", cbPtr )
       → @DllStaticImport 调 webui_bind_sl( win, "onClick", cbPtr )
[原生] webui_bind_sl:
       id = webui_bind( win, "onClick", &trampoline )   // 注册原生 trampoline
       map[id] = cbPtr                                   // bind_id → SL 节流点
[JS] 用户点击 → webui 调用 trampoline( webui_event_t* e )
[原生] trampoline(e):
       slCb = map[e->bind_id]                            // 取回 SL 节流点
       ((void(*)(int64_t))slCb)( (int64_t)e )            // 重入 VM
[VM] 执行 SL 方法 onClick( Int64 eventPtr ):
       name = SLang.WebUI.getArgString( eventPtr, 0 )    // 经 webui_get_string_at
       SLang.WebUI.returnString( eventPtr, "Hello "+name )// 经 webui_return_string
```

### 3.3 trampoline 池与 bind_id 映射（原生层实现，见 `04` §3）

- `webui_bind_sl` 每次调用：`webui_bind` 返回递增的 `bind_id`（size_t），原生层把
  `bind_id → cbPtr` 存进一张动态映射表；
- 所有 bind 共用**同一个** `trampoline(webui_event_t*)`，它读 `e->bind_id` 查表取
  `cbPtr` 并调用。无需为每个 bind 生成独立函数（规避运行时代码生成 / 平台可执行内存难题）。
- 映射表随 `webui_destroy` / `webui_exit` 清理；容量按实际需要动态增长（默认预留 1024）。

### 3.4 SLang 处理函数约定

```sl
// 处理函数：签名固定 static void (Int64 eventPtr)
// eventPtr 即 webui_event_t*，由 getArg*/return* 系列读取与回写
@DllStaticImport( "webui_lib", "webui_get_string_at_sl" )
static string _getArgStr( Int64 e, Int64 i ) { ret "" }

static void onClick( Int64 e )
{
    string name = WebUI.getArgString( e, 0 )
    WebUI.returnString( e, "Hello, " + name )
}
```

支持 lambda（SLang 函数闭包）绑定到 `createCallback` 的 methodId 形式（见 `03` §4）。

## 4. 线程模型（第一风险，必须决策）

webui 的 `webui_config`：

- `ui_event_blocking`（全局）默认 **False** → 每个 UI 事件在**新的非阻塞线程**处理；
- `webui_set_event_blocking(window, bool)` 可针对单窗设为 True → 单线程串行处理。

**SLang VM 重入并发安全是未知数**（VM 是否支持多线程并发执行同一 VM 实例未验证）。
若 webui 多线程并发触发回调、同时重入 VM，可能破坏 VM 内部状态。

### 4.1 决策（默认安全模式）

- **P1 默认开启 `webui_set_event_blocking(window, true)`**（单窗串行），等价于把 webui
  事件处理收敛到单一线程，**消除并发重入**；
- 全局亦可在模块初始化时 `webui_set_config(ui_event_blocking, true)`；
- 这样 `createCallback` 回调节流点的重入是**串行**的，与 SLang 当前 VM 模型兼容。

### 4.2 进阶（后续，非 P1）

- 多客户端（`multi_client`，Web 应用形态）需要 VM 真正线程安全 → 列为后续研发项
  （见 `07` 风险），P1 不支持 `multi_client` 模式。
- 若需并行，可考虑「回调只入队、主线程 `wait` 循环里统一派发到 VM」，但增加复杂度，
  P1 不做。

## 5. 字符串与内存约定

- webui `get_string_*` 返回指针指向 webui 内部缓冲，**回调期间有效**；SLang VM 在返回
  瞬间把内容拷进自身 string，故只需保证「返回那一刻有效」即可（与 Mysql `slm_error`
  同约定）。
- `webui_return_string(e, s)` 的 `s` 由 SLang 侧 string→utf8 临时缓冲提供，webui 内部
  会拷贝，调用后即失效，安全。
- `webui_malloc/webui_free` 仅在需要手动管理原生内存时使用（如 `send_raw` 大数据），
  常规绑定无需触碰。
- `webui_clean()` 在 `webui_wait()` 返回后由 SLang 收尾调用，释放全部资源。

---

## 6. 模块初始化与收尾

- **初始化**：`SLang.WebUI.init()`（模块加载时或首次使用时）调用
  `webui_set_config(ui_event_blocking, true)` + 初始化原生层映射表；可缓存 SLang 版本信息。
- **收尾**：`webui_wait()` 阻塞至所有窗口关闭；之后调用 `webui_clean()`。
- **异常退出**：若 SLang 程序异常，`webui_exit()` 可强制关闭所有窗口（由 SLang 宿主
  的退出钩子触发）。

## 7. 与 SLang FFI 的能力对齐（确认无阻塞点）

| 需求 | SLang FFI 能力 | 是否覆盖 |
|---|---|---|
| 窗口/属性/JS 直调 | `@DllStaticImport` 标量 ≤6 参 | ✅ |
| 事件读取/返回 直调 | 同上 | ✅ |
| 输出缓冲区 `webui_script` | 原生封装 `->string` | ✅（`04` §4） |
| C→SL 回调 | `FFI.StaticLibrary.createCallback("ptr->void")` + 原生 trampoline | ✅ |
| `webui_event_t` 不透明结构 | 仅持 `ptr`，经 `get_*` 拆字段 | ✅ |
| 仅 x64 | SLang FFI 仅 x64（见 `ffi.md`） | ✅ webui 同 x64 构建 |
