## 1. 资源与组件的分工

这是全章最重要的一条：**资源不等于组件**。

| 概念 | 归属 | 可否共享 | 例子 |
|---|---|---|---|
| 资源（Resource） | Render 侧数据对象 | ✅ 多个节点共用同一实例 | `Mesh` / `Material` / `Shader` / `Texture` |
| 组件（Component） | 引擎侧节点成员 | ❌ 每个实例只属一个 GameObject | `Renderer` / `MeshFilter` / 挂到节点上的材质引用槽 |

Unity 里 `MeshFilter.sharedMesh` 与 `Renderer.sharedMaterial` 共享的正是「资源」；本模块沿用同一口径：
**一个 Material 实例可被多个 GameObject 的 Renderer 引用，合成一个批次；一个 Renderer 组件不能被两个节点挂。**

## 2. Render 侧门面【已落盘】

### 2.1 Mesh

| 签名 | 说明 |
|---|---|
| `Mesh.cube(Float32 size)` | 静态工厂，生成单位立方体顶点 |
| `getTriangles()` | 取三角形索引数据 |

另有动态网格上传路径：`RenderPipeline.uploadMesh(slot, ptr, n)` 把顶点数据写到指定槽位，供 RenderObject 按槽引用（第 05 章展开）。

### 2.2 Material

| 签名 | 说明 |
|---|---|
| `void setTexture(...)` / `RenderTexture getTexture()` | 贴图读写 |
| `void setShader(Shader s)` | 绑定着色器 |
| `Material clone()` | 复制材质实例（复制后合批键随之不同） |
| `resolveProgram()` | 解析出实际 shader program，**合批键的输入** |

### 2.3 Shader

| 签名 | 说明 |
|---|---|
| `Shader(string name, ...)` | 构造；RenderTest 使用固化槽名，如 `Shader("SlPhong", ...)` |
| `static Shader find(string name)` | 按名字找内置 shader |
| `bool compile()` | 编译 |
| `setUniform*`（系列） | 参数写入 |

当前可用效果为 Render 固化的 5 种（如 SlPhong 等），**不支持运行时加载 `.shader` 文件**。自定义效果走 Shader 对象的字符串构造与 uniform 参数，不新建文件。

### 2.4 Texture

| 签名 | 说明 |
|---|---|
| `static Texture load(string path)` | 从文件加载（需 `SLangImage` 模块 + `import SLangImage;`） |
| `sample(...)` / `fill(...)` | 采样 / 填充 |

纹理可经 `Material.setTexture` 进入材质，也可直接设置到 RenderObject（`setTexture(RenderTexture)`）。

### 2.5 Renderer（`extends Component`）

| 签名 | 说明 |
|---|---|
| `void setMesh(Mesh m)` / `Mesh getMesh()` | 网格引用 |
| `void setMaterial(Material m)` / `Material getMaterial()` | 材质引用 |
| `void setVisible(bool v)` | 可见开关 |
| `bool render()` | ⚠ **当前恒返回 false**：旧 `Render.drawMesh` 已移除，绘制提交统一改走命令缓冲（`CommandBuffer.drawMesh` / `ScriptableRenderContext`），由引擎层合批器接管（第 05 章） |

> 结论：不要在自己的脚本里调用 `Renderer.render()` 期待它画东西。可见节点由帧循环收集后交给合批器，统一提交 RenderObject。

## 3. 引擎侧组件绑定【已落盘（数据层）】

### 3.1 节点上的典型组合

```
GameObject "Cube"
  ├─ Transform
  ├─ MeshRef            ← 网格引用组件（引擎侧，可多节点共享同一顶点数据）
  └─ MaterialRef        ← 材质引用组件（共享同一 MaterialData 实例 → 同批次）
```

已落盘组件接口（`SimGameEngine/*.sl`；与 SLangRender 门面的映射在 Submit 段做）：

```sl
public class MeshRef extends Behaviour
{
    public Int32 meshKind              # 内置网格枚举值（Render MESH_* 数值由提交方映射）
    public Int32 meshSlot              # -1 内置网格；>=0 uploadMesh 动态槽
    public bool  visible
    public bool  hasVertexData         # true = vertices 携带模型空间顶点（可烘焙合批）
    public List<Float32_3> vertices    # x,y,z 每顶点（注意 `dynamic` 是关键字）
    void setVertices( List<Float32_3> v )
    void useTriangle/useQuad/useCube( Float32 size )   # 实例化内置网格顶点
    # static 工厂 triangleVertices/quadVertices/cubeVertices 模块内可用，
    # 消费方勿直调（跨模块静态方法 IR 错位，doc/10 §6）
}

public class MaterialRef extends Behaviour
{
    public MaterialData material       # 共享资源引用（实例身份 = 引用）
    public Int32 renderQueue           # 0 = 跟随材质（默认）；正值覆盖
    public bool  instanceColorOverride # true 时 instanceColor 进合批键（拆批）
    public Float32_3 instanceColor
    public Int32 animatedMode          # 批次级动画参数（P5 前手动入口）
    public Float32 animatedSpeed
}

public class MaterialData               # 可共享材质数据资源（非组件）
{
    public Int32 assetId               # create() 分配（调试用；身份=引用）
    public string name
    public Int32 programId             # 对应 Render resolveProgram() 结果
    public Int32 textureId             # 对应 Render 贴图句柄 id
    public Float32_3 color
    public Float32 specular
    public bool castShadow
    public Int32 renderQueue           # 默认 2000；>=2500 走透明段
    public Int32 animatedMode
    public Float32 animatedSpeed
    static MaterialData create( string name )
}
```

合批器入口（doc/05 §3）：`Batcher.collect(scene, cullMask)` → `build()` → `groupAt(i)` / `groupCount()`；`BatchGroup.bakeVerticesInto(List<Float32_3>)` 生成世界空间顶点。

CGameObject 上同时挂多个 Renderer 会被拒绝（第 02 章「同类组件唯一」）。需要多个可绘制部分时建子节点，各自挂自己的 Renderer / MeshRef / MaterialRef；它们仍可共享同一个 Material 实例，因此可以被合批到一起（子节点的 world 变换不同，但批次键相同）。

### 3.2 材质实例与合批的关系

| 写法 | 结果 |
|---|---|
| 10 个节点引用同一个 `Material m` | **可以合批**：`resolveProgram()` 相同、材质实例相同 |
| 10 个节点各自 `m.clone()` | **不能合批**：材质实例不同（除非后续做参数聚合成 UBO 数组） |
| 同一 Material 但不同 `renderQueue` | **不能合批**：渲染顺序语义不同 |
| 不同 Shader 但同一 Material 实例 | 不可能（Material 一旦 `setShader` 就影响所有引用者，包括其它节点）|

> 因此修改共享 Material 会影响所有引用它的节点。需要差异化的节点用 `clone()`，代价是失去合批。

## 4. 资源生命周期

| 阶段 | 动作 |
|---|---|
| 创建 | `Mesh.cube()` / `Material()` / `Shader()` / `Texture.load()` 由调用方持有 |
| 挂载 | 组件**只保存引用**，不接管所有权 |
| 共享 | 只要还有组件引用，资源就必须存活 |
| 释放 | 引用方全部销毁后，由资源表（设计稿）统一回收；RenderObject 句柄由 `destroy()` 释放 |
| 后端切换 | 管线 / 纹理句柄全部失效，**必须全量重建资源与场景**（`RenderTest.sl` 与 `13-Usage-Guide.md` 均有证据） |

当前尚无资源表实现，实践中由主程序自己维护 `Array<Material>` / `Array<Texture>` 持有引用，在 Scene 切换时统一重建。

## 5. 示例：从资源到可见节点（设计稿写法）

```sl
import Std;
import Math;
import SLangRender;

# 共享资源：一次创建，多处引用
Mesh cubeMesh = Mesh.cube( 1.0f )
Shader litShader = Shader( "SlPhong" )
litShader.compile()
Material litMat = Material()
litMat.setShader( litShader )

GameObject a = GameObject.create( "A" )
GameObject b = GameObject.create( "B" )

a.addComponent<MeshRef>().mesh = cubeMesh
a.addComponent<MaterialRef>().material = litMat
b.addComponent<MeshRef>().mesh = cubeMesh
b.addComponent<MaterialRef>().material = litMat     # 同一实例 → 同一批次

MaterialRef ar = a.getComponent<MaterialRef>()
ar.renderQueue = 2000
ar.specular = 0.35f
```

> 注：上例中的 `GameObject` / `MeshRef` / `MaterialRef` 为第 02/03 章设计接口，落地前不可直接编译；`Mesh` / `Shader` / `Material` 三行则是 Render 现有 API，可在 RenderTest 同款工程中运行（需 `import SLangRender;` 与正确模块引用）。

## 6. 已知坑与注意

1. **不要调用 `Renderer.render()`**：它恒返回 false；绘制提交归合批器（第 05 章）。
2. **不要用 `m.clone()` 做「只是颜色不同」的批量对象**：克隆导致批次分裂；颜色差异应通过合批后 RenderObject 的 `setColor()` 写实例数据（前提：shader 支持实例色）。
3. 纹理加载依赖 `SLangImage` 模块且必须显式 `import SLangImage;`，否则会出现符号解析失败。
4. `Material.resolveProgram()` 是合批键的唯一可信来源，不要拿 Shader 对象名自己拼 key（固化槽名与 program 并非一一对应）。
5. 动态网格走 `uploadMesh(slot, ptr, n)` 时，slot 是**引擎自己分配**的槽位号，和 MeshRef.meshSlot 必须一致；不同步会造成引用到旧网格数据。
6. Render 的后端切换会作废旧句柄；切换后本章所有资源对象都要按 §4 重建，不要缓存跨后端的 Material / Texture。
