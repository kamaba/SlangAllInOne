# SimGameEngine · 06 相机、光照与探针节点

> 状态：Camera / Light 门面【已落盘】（Render 侧）；Probe【设计稿】；节点化挂载【设计稿】。
> 前置阅读：`03-场景树与变换层级.md`（layer / cullMask）、`05-合批与RenderObject提交.md`（提交顺序）。

---

## 1. 设计原则

Camera / Light / Probe 都是**挂在 GameObject 上的组件**，不是游离对象：

- 挂到哪个节点，就跟随哪个节点的 Transform（父节点移动，相机 / 光源跟着走）；
- 禁用节点后组件自动退出本帧收集（第 02 章激活传播）；
- 同一 GameObject 同类组件唯一：一个节点只挂一个 Camera / 一个 Light；多相机 / 多光源建多个节点。

## 2. Camera【Render 已落盘】

### 2.1 门面签名（`Render/SLangRender/Camera/Camera.sl`）

| 签名 | 说明 |
|---|---|
| `Camera extends Component` | 来自 Render 模块，继承 Std 的 Component |
| `worldToViewportPoint(...)` | 世界坐标 → 视口坐标 |
| `screenPointToRay(...)` | 屏幕点 → 世界射线（配合 `Ray` / `Bounds` 做拾取，第 03 章） |
| `getFrameSettings()` | 取得帧设置，供管线使用 |

### 2.2 管线侧相机参数

`RenderPipeline` 提供两个相机入口：

```sl
pipe.setCamera( cullMask, left, right, bottom, top )   # 设置剔除掩码与视锥边界
pipe.addCamera( depth )                                # 多相机 depth 排序
```

`cullMask` 是 32 位掩码，第 N 位对应 layer N：`mask |= (1 << layer)`。只有节点的 layer 命中掩码才会进入可见候选（第 03 章 §3 / 第 05 章合批键分量 4）。

### 2.3 多相机

- 每个激活的 Camera 组件贡献一组 `cullMask / 视锥 / depth`；
- 按 `depth` 从小到大渲染，后绘制的相机覆盖前面的输出（与 Unity 的 Camera Depth 一致）；
- Render 05 文档把「相机栈（Camera Stack）」列为 M7 不承诺项：目前是平铺 depth 列表，**没有** Base / Overlay 叠加语义；需要分屏时用两个相机 + 不同 viewport 参数自行组织。

### 2.4 挂载示例（设计稿写法）

```sl
GameObject camGo = GameObject.create( "Main Camera" )
Camera cam = camGo.addComponent<Camera>()       # Render 侧 Camera 组件
camGo.transform.setLocalPosition( Float32_3( 0.0f, 2.0f, -10.0f ) )

# 帧循环中由引擎收集：
Int32 cullMask = 0x00000001                      # 只画 layer 0
pipe.setCamera( cullMask, -1.0f, 1.0f, -1.0f, 1.0f )
```

## 3. Light【Render 已落盘】

### 3.1 门面签名（`Render/SLangRender/Camera/Light.sl`）

| 签名 | 说明 |
|---|---|
| `static Light directional(...)` | 平行光工厂 |
| `static Light point(...)` | 点光源工厂 |
| `static Light spot(...)` | 聚光灯工厂 |
| `void applyTo( pipe, slot )` | 把光源参数写入管线的指定灯光槽 |

### 3.2 灯光槽位

Render 侧用有限数量的灯光槽（由管线决定），引擎侧的收集规则：

1. 遍历激活节点的 Light 组件；
2. 按类型与强度排序：directional 优先，再 point / spot；
3. 依次调用 `light.applyTo(pipe, slot)`，超出槽位数的光源本帧不参与渲染（保留节点，下一帧可能进入槽位）。

灯光与合批的关系：光源是**全局参数**，不是合批键分量；同一批对象接受同样的灯光槽配置。若场景需要不同灯光影响不同区域，用 layer 分成不同批次 + 多次渲染（受限于多相机 depth 机制）。

### 3.3 挂载示例（设计稿写法）

```sl
GameObject sunGo = GameObject.create( "Sun" )
Light sun = Light.directional( /* 方向 / 颜色 / 强度，签名以 Render 源码为准 */ )
sunGo.addComponent<Light>()                       # 引擎侧包装组件，持有 Light 门面引用
sun.applyTo( pipe, 0 )                            # 写入 0 号灯光槽
```

> 注：`Light` 的三个静态工厂参数列表请以 `../Render/SLangRender/Camera/Light.sl` 实际签名为准；本文只固化「工厂 + applyTo」的调用契约。

## 4. Probe【设计稿】

### 4.1 目标形态

对齐 Unity 的两类探针：

| 组件 | 数据 | 作用范围 |
|---|---|---|
| `ReflectionProbe` | cubemap 句柄、盒子大小、混合距离、刷新模式 | 空间内反射采样 |
| `LightProbe` | 球谐系数、插值位置 | 动态物体间接光插值 |

拟定接口：

```sl
public class Probe extends Component
{
    public int   probeType          # 0=Reflection, 1=Light
    public Bounds influenceBounds   # 影响范围（第 03 章已落盘类型）
    public Float32 blendDistance
    public bool  refreshOnAwake
}
```

### 4.2 现状边界

Render 侧**没有**反射探针 / 光照探针的渲染能力（13 阶段管线里也没有对应 Pass）。因此：

- v0.1 只落数据结构与节点挂载，采集 / 上传 / 采样全部不实现；
- 需要反射效果的材质仍走 `Material.setTexture` 的静态贴图路径；
- 禁止在文档中把 Probe 描述为「可用」——它是为后续扩展保留的位置。

## 5. 与拾取 / UI 的协作

- 相机 `screenPointToRay()` 产生的 `Ray` 可直接交给第 03 章的 `Bounds.intersectsRay()` / `Plane.raycast()` 做世界拾取；
- UI 命中检测优先于世界拾取（第 08 章），相机拾取只在 UI 未消费事件时执行；
- UI 建议独占一个 layer，并在主相机 cullMask 中**不**包含该 layer，避免 UI QUAD 被 3D 相机重复收集。

## 6. 已知坑与注意

1. `cullMask` 与节点 layer 必须一致：相机位掩码没开对应 layer，对象不会画；合批键里 layer 不同也会拆批。
2. `setCamera` 要在 `renderFrame` 之前调用；阶段中途改相机参数会让本帧剔除结果与实际渲染不一致。
3. `addCamera(depth)` 是平铺排序，不是 Unity Camera Stack；不要依赖「Overlay 相机继承 Base 输出」的行为。
4. 灯光槽数量有限，优先级排序要保证主光（directional）在前；超槽位光源静默丢弃，调画面时别误判为材质问题。
5. 相机挂在有旋转的父节点下会跟着转；需要固定朝向时把相机节点挂到 Scene 根，或每帧反向补偿父旋转。
6. Probe 目前仅是数据占位，没有渲染侧实现；写了 Probe 组件不会改变画面。
