## 1. 定位与范围

| 能力 | v0.1 范围 | 远期 |
|---|---|---|
| 刚体运动（重力 / 速度 / 阻力） | ✅ 目标 | — |
| 碰撞响应（法向冲量 / 摩擦 / 恢复） | ✅ 目标 | — |
| 连续碰撞检测（CCD） | ⚠ 仅高速小物体 | 通用 CCD |
| 关节 / 约束（铰链 / 弹簧 / 布娃娃） | ❌ 未纳入 | 后续版本 |
| 软体 / 布料 / 流体 | ❌ 未纳入 | 不承诺 |
| 第三方物理引擎接入（PhysX / Box2D） | ❌ 当前不接 | 可评估替换后端 |

物理只处理「运动 + 响应」，不处理渲染；渲染侧只看到最终 Transform（第 03 章）。

## 2. Rigidbody【设计稿】

```sl
public class Rigidbody extends Component
{
    public Float32 mass = 1.0f
    public Float32 drag = 0.0f             # 线性阻力
    public Float32 angularDrag = 0.05f
    public bool   useGravity = true
    public bool   isKinematic = false      # true = 脚本控制，不受力/碰撞影响
    public Float32 restitution = 0.0f      # 恢复系数（弹性）
    public Float32 friction = 0.6f

    public Float32_3 velocity
    public Float32_3 angularVelocity

    public void addForce( Float32_3 force )
    public void addImpulse( Float32_3 impulse )
    public void movePosition( Float32_3 target )     # kinematic 用
}
```

三种刚体状态：

| 状态 | 行为 |
|---|---|
| Dynamic | 受重力、受力、参与碰撞求解 |
| Kinematic | 脚本 `movePosition` 驱动，能推开 dynamic，但自身不被推动 |
| Static（无 Rigidbody，仅有 Collider） | 固定不动，作为碰撞背景 |

## 3. 固定步长积分

物理**必须**跑在 `fixedUpdate`（第 09 章 §4），不能跟着渲染帧走：

```
每帧：
  acc += min(rawDt, maxDt) * timeScale
  while acc >= fixedDt && steps < 5:
      1. 施加重力 → velocity
      2. 施加外力 / 阻力 → velocity
      3. 预测位置 → 更新 worldBounds
      4. 碰撞检测（第 11 章）→ 接触列表
      5. 求解接触（§4）→ 修正 velocity / position
      6. position += velocity * fixedDt
      7. 写回 Transform（标脏）
      acc -= fixedDt
```

积分用**半隐式欧拉**（先更新速度、再用新速度更新位置）：比显式欧拉稳定，实现成本几乎相同。

## 4. 接触求解【设计稿】

每对接触产生一个 `ContactInfo`（第 11 章：point / normal / penetration）：

### 4.1 位置修正

先解决穿透，避免物体陷进彼此：

```
correction = normal * max(penetration - slop, 0) * percent / totalInvMass
bodyA.position += correction * invMassA
bodyB.position -= correction * invMassB
```

`slop ≈ 0.01`、`percent ≈ 0.8`：留一点允许穿透量、只修正 80%，避免抖动。

### 4.2 法向冲量

```
relV = velocityB - velocityA
vn   = dot( relV, normal )
if vn > 0: 跳过（正在分离）
j    = -(1 + restitution) * vn / (invMassA + invMassB)
velocityA -= normal * j * invMassA
velocityB += normal * j * invMassB
```

### 4.3 切向摩擦

```
tangent = normalize( relV - normal * dot(relV, normal) )
jt = clamp( -dot(relV, tangent) / (invMassA + invMassB), -j * friction, j * friction )
```

同一接触点迭代 4~8 次（顺序冲量法），堆叠稳定性随迭代次数提升。

### 4.4 休眠（Sleeping）

速度低于阈值持续若干步的刚体置为 sleeping，跳过积分与求解；被碰撞或外力唤醒。大量静止物体时这是主要性能优化。

## 5. 与变换的同步

```
物理世界（fixedUpdate）  ──写回──►  Transform.world*
                                      │
                                      ├─ 渲染插值（alpha = acc / fixedDt）
                                      └─ 合批收集（第 05 章第 6 步）
```

- 物理写的是 Transform 的**世界**状态；Transform 再反算 local（有父节点时）；
- 渲染用 `previous` 与 `current` 两个世界变换按 `alpha` 插值，避免固定步长与高刷新率不同步导致的抖动；
- 合批在第 6 步读取的是插值后的变换（第 09 章帧序：物理 → 变换刷新 → 收集）。

**不要**在 `update()` 里直接改带 Rigidbody 节点的 Transform：下一次物理步会用刚体状态覆盖它。要移动动态刚体请用 `addForce` / `addImpulse`；要瞬移请同时重置 `velocity` 与 Transform。

## 6. 高速物体与 CCD

离散检测在一步内位移超过碰撞体尺寸时会「穿墙」：

- 缓解方案一：提高固定步长频率（代价：求解成本上升）；
- 缓解方案二：对高速小物体做射线扫掠（`Ray.fromTo(oldPos, newPos)` + `intersectBounds`，第 03 章已落盘），命中则把位置钳到接触点前；
- v0.1 只实现方案二的选择性 CCD，不做通用 CCD。

## 8. 已知坑与注意

1. **物理绝不能放进 `update()`**：不同帧率会得到不同结果；固定步长是正确性的前提。
2. **别同时用 `isKinematic` 与力**：kinematic 刚体忽略 force/impulse，只接受 `movePosition`。
3. **恢复系数 > 1 会持续增能**：通常限制在 [0, 1]；需要弹跳增强应显式施加冲量。
4. **堆叠抖动**：位置修正百分比过高、迭代次数过少、slop 为 0 都会导致；按 §4.1 参数起步调。
5. **sleeping 物体不会被触发器唤醒**：需要唤醒时显式调用 `wakeUp()`（拟定接口）或用 kinematic 碰撞体推动。
6. **斜面上的滑动**依赖摩擦实现，v0.1 的切向冲量是近似解；陡坡可能持续下滑，属预期行为。
7. **物理章尚未落盘**：当前项目没有物理系统，本文描述的是目标设计；现有的 `Bounds`/`Plane`/`Ray` 可独立用于简单自定义运动逻辑。
