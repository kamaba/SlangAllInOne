# SimGameEngine · 07 动画与特效

> 状态：Animation / Effect 组件【设计稿】；RenderObject 内置动画模式【已落盘】。
> 前置阅读：`04-渲染资源模型.md`、`05-合批与RenderObject提交.md`、`06-相机光照与探针.md`。

## 1. 两条表现路径

| 路径 | 能力 | 实现位置 | 适用 |
|---|---|---|---|
| A. 内置动画模式 | 色相循环等固化效果，按 `mode + speed` 参数驱动 | Render 的 `RenderObject.setAnimated(mode, speed)` | 批量、轻量、无需逐对象时间轴 |
| B. 自定义动画采样 | 关键帧轨道、Transform 插值、事件 | 本模块 Animation 组件（设计稿） | 需要精确时间轴 / 逐节点控制 |

优先用 A：它不拆批次（同 mode/speed 的对象可同批），成本最低；A 表达不了才上 B。

## 2. 路径 A：内置动画模式【已落盘】

### 2.1 签名

```sl
bool setAnimated( Int32 mode, Float32 speed )
```

`mode` 由管线提供常量，例如 `pipe.ANIM_HUE_CYCLE`；`speed` 是速率（RenderTest 示例用 `0.05f`）。

### 2.2 用法（Render 现有写法）

```sl
SLang.RenderObject tri = pipe.addObject( pipe.MESH_TRIANGLE )
tri.setAnimated( pipe.ANIM_HUE_CYCLE, 0.05f )    # 色相循环
pipe.renderFrame( t, pixels )                     # t 为秒，驱动动画相位
```

### 2.3 合批影响

`mode` / `speed` 是**批次级**参数（第 05 章合批键分量 8）：

- 同 mode + 同 speed → 可同批，一起动；
- 不同 speed → 拆批，即使材质与网格完全相同；
- 不要试图在批次提交后再改某一个对象的动画参数——那会改到整批。

固化效果清单由 Render 侧决定（SlPhong 等 5 种固化 shader 效果 + 对应动画模式），**不支持运行时加载新的动画 shader**。

## 3. 路径 B：Animation 组件【设计稿】

### 3.1 数据模型

```sl
public class AnimationClip
{
    public string name
    public Float32 duration
    public bool   loop
    public Array<AnimationTrack> tracks
}

public class AnimationTrack
{
    public string binding        # "position" / "rotationZ" / "scale" / "color"
    public Array<Keyframe> keys  # { time, value }
}

public class Animation extends Behaviour
{
    public AnimationClip clip
    public Float32 speed = 1.0f
    public Float32 time
    public bool playing

    public void play()
    public void pause()
    public void stop()
    public void evaluate( Float32 t )        # 写回组件宿主节点的 Transform / 材质参数
}
```

### 3.2 采样与帧序

| 帧序位置 | 动作 |
|---|---|
| `update()` | 推进 `time += dt * speed`；`loop` 时对 `duration` 取模 |
| `update()` 末尾 | `evaluate(time)` 把轨道值写到 Transform / Renderer / MaterialRef |
| `lateUpdate()` | 相机跟随等依赖最终动画姿态的逻辑 |
| 变换刷新 | 脏 Transform 参与第 03 章的自顶向下重算 |
| 可见 / 合批 | 动画后的世界变换参与第 05 章顶点烘焙 |

**关键顺序**：必须先采样再收集批次。若合批已完成后再改 Transform，本帧画面仍是旧位置（下一帧才生效）。

### 3.3 动画对象与合批的冲突

路径 B 会让节点每帧改变世界变换，而第 05 章的默认合批策略是把世界变换**烘焙进顶点**：

- 每帧变换都变 → 每帧都要重新 `uploadMesh` → 合批收益被上传成本抵消；
- 建议：运动对象走「单对象批」例外路径（变换写 RenderObject 字段，不烘焙），静态对象才参与合并；
- 需要大量同类运动对象时，优先用路径 A 的内置模式（GPU 侧按 t 计算，不重传顶点）。

## 4. Effect 组件【设计稿】

### 4.1 目标形态

```sl
public class Effect extends Behaviour
{
    public int    effectType       # 0=粒子, 1=拖尾, 2=闪光, 3=后处理挂点
    public Float32 duration
    public bool    loop
    public Material effectMaterial # 使用共享材质，保持可合批

    public void play()
    public void stop()
}
```

### 4.2 与 Render 阶段的对应

| Effect 类型 | 实现路径 | 备注 |
|---|---|---|
| 闪光 / 变色 | 路径 A：`setAnimated(mode, speed)` | 最省，进批 |
| 拖尾 / 粒子 | 动态网格 `uploadMesh` + Effect 组件每帧更新顶点 | 当前无内置粒子系统，需自己写更新逻辑 |
| 屏幕后处理 | Render 13 阶段的 `postProcess` 阶段 | 参数须在该阶段前写入；Render 当前只提供固化后处理效果 |
| 光源闪烁 | 第 06 章 Light 槽参数逐帧改 | 光源是全局参数，不影响合批键 |

### 4.3 生命周期

- `onEnable()` 时 `play()`，`onDisable()` 时 `stop()`（与 `Behaviour` 钩子一致，第 02 章）；
- `dispose()` 中释放动态网格槽与 RenderObject 句柄，不要留给帧尾兜底；
- 特效结束自动 `destroy()` 节点，帧尾统一回收。

## 5. 事件轨道（可选）

动画常需要在特定时间点触发游戏逻辑（脚步声、命中帧）。设计上不加新的事件系统，直接复用 `Behaviour` 的钩子：

```
Animation.evaluate(t) 检测到跨过关键帧
  → 调用宿主节点上所有 Behaviour 的 onAnimationEvent(name, t)
  → 脚本在钩子中决定播放音效 / 生成特效
```

注意：SLang 当前没有内建委托，事件分发用组件遍历实现，不要用字符串反射式调用。

## 6. 已知坑与注意

1. `setAnimated` 作用于整个 RenderObject（批次），不同相位的对象不能塞进同一批。
2. `setAnimated` 的 `t` 来自 `renderFrame(t, dstPtr)` 的秒数参数；自己维护的 `Animation.time` 要与之对齐，否则画面相位与逻辑不一致。
3. 固化 shader / 动画模式数量有限，运行时加载 `.shader` 文件不在当前能力内。
4. 频繁变动的 Transform 会导致动态网格每帧重传；这是合批的固有成本，不是 bug。
5. Effect 组件尚未落盘；当前可用的是「手写 `setAnimated` + `uploadMesh`」路径。
6. 动画中销毁节点：先 `stop()` 再 `destroy()`，避免 `evaluate()` 在帧尾继续写已标记销毁的 Transform。
