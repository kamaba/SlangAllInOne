## 2. Rigidbody【已落盘】

```sl
public class Rigidbody extends Behaviour   # 源码 Rigidbody.sl
{
    public Float32 mass = 1.0f
    public Float32 drag = 0.0f             # 线性阻力
    public Float32 angularDrag = 0.05f
    public bool   useGravity = true
    public bool   isKinematic = false      # true = 脚本控制，不受力/碰撞影响
    public Float32 restitution = 0.0f      # 恢复系数（弹性）
    public Float32 friction = 0.6f

    public Float32_3 velocity
    public Float32_3 angularVelocity
    public bool   sleeping                 # 休眠（PhysicsSystem 维护）

    public void addForce( Float32_3 force )        # 累积到本固定步，步末清零
    public void addImpulse( Float32_3 impulse )    # velocity += impulse/mass
    public void movePosition( Float32_3 target )   # 瞬移（kinematic 驱动用）
    public void wakeUp()
}
```

挂载用「调用方构造 + 引擎去重挂载」（方法级泛型构造不可用，doc/10 §6）：

```
Rigidbody rb = Rigidbody()
go.addComponent( rb )
rb.mass = 1.0f
```

三种刚体状态：

| 状态 | 行为 |
|---|---|
| Dynamic | 受重力、受力、参与碰撞求解 |
| Kinematic | 脚本 `movePosition` 驱动，能推开 dynamic，但自身不被推动 |
| Static（无 Rigidbody，仅有 Collider） | 固定不动，作为碰撞背景 |

## 3. 固定步长积分【已落盘】

物理**必须**跑在 `fixedUpdate`（第 09 章 §4），不能跟着渲染帧走。接入方式（Application 固定步内，物理优先、退化为纯碰撞）：

```
app.physicsSystem = PhysicsSystem()
app.collisionSystem = CollisionSystem()   # 可选：无碰撞响应的自由运动可不挂
```

落盘流程与下述伪码一致，另在步末追加了休眠判定（见 §4.4）：

```
每帧：
  acc += min(rawDt, maxDt) * timeScale
  while acc >= fixedDt && steps < 5:
      1. 施加重力 → velocity
      2. 施加外力 / 阻力 → velocity
      3. 预测位置 → 更新 worldBounds
      4. 碰撞检测（第 11 章）→ 接触列表
      5. 求解接触（§4）→ 修正 velocity / position
      6. position += velocity * fixedDt
      7. 写回 Transform（标脏）
      acc -= fixedDt
```

积分用**半隐式欧拉**（先更新速度、再用新速度更新位置）：比显式欧拉稳定，实现成本几乎相同。

## 4. 接触求解【已落盘】

每对接触产生一个 `ContactInfo`（第 11 章：point / normal / penetration）：

> ⚠ **实现坑（重要）**：`ContactInfo.normal` 的引擎约定是 **B→A**（从 other 指向自身，doc/11 §2），与本章伪码隐含的 Unity 风格 **A→B** 相反。直接照搬伪码的「`vn > 0` 跳过（正在分离）」会把接近判定反相——冲量只在分离时触发，接触反而把物体加速推进墙里（SimPhysicsTest 首轮实证症状：球加速穿地、vx 被越推越大）。落盘版 `PhysicsSystem.solveContacts` 按 B→A 约定取「`vn > 0` = 接近才求解」，摩擦 clamp 用 `|j|` 区间。

### 4.1 位置修正

先解决穿透，避免物体陷进彼此：

```
correction = normal * max(penetration - slop, 0) * percent / totalInvMass
bodyA.position += correction * invMassA
bodyB.position -= correction * invMassB
```

`slop ≈ 0.01`、`percent ≈ 0.8`：留一点允许穿透量、只修正 80%，避免抖动。

### 4.2 法向冲量

```
relV = velocityB - velocityA
vn   = dot( relV, normal )
if vn > 0: 跳过（正在分离）
j    = -(1 + restitution) * vn / (invMassA + invMassB)
velocityA -= normal * j * invMassA
velocityB += normal * j * invMassB
```

### 4.3 切向摩擦

```
tangent = normalize( relV - normal * dot(relV, normal) )
jt = clamp( -dot(relV, tangent) / (invMassA + invMassB), -j * friction, j * friction )
```

同一接触点迭代 4~8 次（顺序冲量法），堆叠稳定性随迭代次数提升。

### 4.4 休眠（Sleeping）【已落盘】

速度低于阈值（`sleepLinearThreshold=0.05`）持续 `sleepTimeThreshold=0.5` 秒的刚体置为 sleeping，跳过积分与求解；被外力/冲量/显著相对速度碰撞唤醒。大量静止物体时这是主要性能优化。

**实现时机坑**：休眠判定必须放在**接触求解之后**（step 末尾）——若放在积分前，接触中的刚体每步先被加重力（速度恒 ≈ g·dt > 阈值），判定永不满足、永不入睡。

## 5. 与变换的同步

```
物理世界（fixedUpdate）  ──写回──►  Transform.world*
                                      │
                                      ├─ 渲染插值（alpha = acc / fixedDt）
                                      └─ 合批收集（第 05 章第 6 步）
```

- 物理写的是 Transform 的**世界**状态；Transform 再反算 local（有父节点时）；
- 渲染用 `previous` 与 `current` 两个世界变换按 `alpha` 插值，避免固定步长与高刷新率不同步导致的抖动；
- 合批在第 6 步读取的是插值后的变换（第 09 章帧序：物理 → 变换刷新 → 收集）。

**不要**在 `update()` 里直接改带 Rigidbody 节点的 Transform：下一次物理步会用刚体状态覆盖它。要移动动态刚体请用 `addForce` / `addImpulse`；要瞬移请同时重置 `velocity` 与 Transform。

## 6. 高速物体与 CCD【选择性 CCD 已落盘 2026-11-16（方案二）】

离散检测在一步内位移超过碰撞体尺寸时会「穿墙」：

- 缓解方案一：提高固定步长频率（代价：求解成本上升）；
- 缓解方案二【✅ 已落盘】：对高速小物体做射线扫掠（`Ray.fromTo(prev, now)` + `Bounds.intersectRayDistance`），命中则把位置钳到命中面外 `ccdRadius` 处，并清速度的法向分量（沿本步位移方向）、保留切向；
- 通用 CCD（每对形状连续检测）不做。

落盘 API（`Rigidbody` 新增字段）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `bool ccdEnabled` | false | 高速小物体开启；慢速物体无需（有步内位移阈值门槛） |
| `Float32 ccdMotionThreshold` | 0.5 | 步内位移超过此值才扫掠（挡掉慢速物体的无谓扫掠） |
| `Float32 ccdRadius` | 0.5 | 钳位余量（≈碰撞体半径，中心停在命中面外扩该值处） |

实现位置与帧序：`PhysicsSystem.step` 在 `collisionSystem.step`（离散检测）之后、`solveContacts` 之前执行 `ccdClip`——扫掠用本步刷新的碰撞体 AABB（`CollisionSystem.sweepDistance(exclude, from, to)` 公共查询，排除自身节点，返回最近命中距离/未命中 -1）。

v0.1 边界（偏离说明）：

- 离散检测基于钳位前位置，高速穿透步的 Enter/Exit 事件可能错拍（下一固定步恢复）；需要精确穿透帧事件时用触发器 + 低速；
- 命中判定是「中心线 vs AABB」，钳位余量靠 `ccdRadius` 手动对齐碰撞体尺寸（球=半径、胶囊=半径、盒=对角线一半近似）；
- 法向清零用的是本步位移方向（非接触面法线），斜撞时切向保留近似成立（`SimPhysicsTest` PH14 验证）。

## 8. 已知坑与注意

1. **物理绝不能放进 `update()`**：不同帧率会得到不同结果；固定步长是正确性的前提。
2. **别同时用 `isKinematic` 与力**：kinematic 刚体忽略 force/impulse，只接受 `movePosition`。
3. **恢复系数 > 1 会持续增能**：通常限制在 [0, 1]；需要弹跳增强应显式施加冲量。
4. **堆叠抖动**：位置修正百分比过高、迭代次数过少、slop 为 0 都会导致；按 §4.1 参数起步调。
5. **sleeping 物体不会被触发器唤醒**：需要唤醒时显式调用 `wakeUp()`（拟定接口）或用 kinematic 碰撞体推动。
6. **斜面上的滑动**依赖摩擦实现，v0.1 的切向冲量是近似解；陡坡可能持续下滑，属预期行为。
