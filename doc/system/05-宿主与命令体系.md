# 统一宿主 slang（SlangAllInOne）

> 项目定位：把 Front 与 C VM 粘合为单一可执行文件 `slang`，同时承载标准库、测试、工具、文档与发布。
> 入口：`d:/project/lang/SlangAllInOne/Program.cs`（`internal static class Program`，`Main` + `KnownCommands` + `ParseArgs`）。
> 工程：`d:/project/lang/SlangAllInOne/SlangAllInOne.csproj`。repoRoot 探测锚点 = 上溯找 `SlangAllInOne.csproj`。
> 关联：[00-系统总揽](00-系统总揽.md) · [01-全链路流程](01-全链路流程.md) · [09-文档索引](09-文档索引.md)

## 2. 命令分发表

`Program.cs` 的 `KnownCommands`（L74）+ switch（L141）。带 ★ 为高频。

| 命令 | 实现 | 说明 |
|------|------|------|
| ★裸工程路径 | `Program.RunProject`（非已知命令/非包文件 → `Command="projectrun"`） | **编译即运行**：Front 编译 → SLB 内存直传 → C VM 执行 |
| `compile` | `Program.RunCompile` → `FrontendService.Compile` | 只编译 |
| ★`run` / `run-disk` | `Program.RunDisk`（parse 期归一为 run-disk） | 只运行已编译产物 |
| `publish` | `Publish/PublishCommand.Run` | 发布（exe/slb/both） |
| `test` | `Program.RunTests` | 逐用例 spawn 自身子进程（Front 静态不可重入） |
| `project` | `Project/ProjectCommand.Run` | 工程配置/扫描/增删改 |
| `new` | `New/NewCommand.Run` | 工程/类脚手架 |
| `lsp` | `Lsp/LspServer.Run` | LSP 服务 |
| `lsp-compile` | `Lsp/LspCompileCommand.Run` | LSP 诊断编译（stdout 结构化 JSON） |
| `ffi-check` | `Ffi/FfiCheckCommand.Run` | FFI 契约校验 |
| `pack-modules` | `Pack/PackModulesCommand.Run` | 模块打包 |
| `version` | `Program.RunVersion` | 自身版本 + Front 版本 |

## 3. P/Invoke 与 C VM 衔接

- 声明：`Backend/CvmInterop.cs`（`internal static class CvmInterop`）。
- C VM 真实导出的宿主入口只有 3 个（`csimple_lang/src/cli/cli.h`，**不是 `cvm_*` 前缀**）：
  1. `cli_main(int argc, char* argv[])` — 经典 argv（run/info）
  2. `cli_run_module_in_memory(json_text, base_dir, flags, program_args, count)` — SLIR JSON 内存运行
  3. `cli_run_module_in_memory_binary(data, data_size, base_dir, flags, program_args, count)` — **SLB 字节内存运行（CvmBackend 主用）**
- 另含平台支撑导入 `SetDllDirectory`（kernel32.dll）、`dlopen`（libdl.so.2, RTLD_GLOBAL）。
- ⚠ `cvm_*` 都是原生库**工程名**（cvm_math_lib、cvm_sl_render_lib、cvm_webui_lib、各插件 cvm runtime），不是导出函数名。

## 4. 编译即运行（裸工程路径）

```
slang SLangCore/test/BaseTest/ProjectTest
  → RunProject
      → FrontendService.Compile        （Front 编译，默认 --export-mode memory）
          → CommandExecutor.Execute    （进程内调 Front）
      → CvmBackend.Locate             （定位 C VM DLL）
      → cvm.RunInMemoryBinary(bytes)  （SLB 零落盘直传）
          → C VM: 装载 → 装配 → vm_run
```

- `--export-mode output|temp`：先落盘 `module.slb`，再 `cvm.RunCli(["run", path])`（磁盘态）。
- stdout/stderr 由 C VM `cli_main` 内 `fflush` 补齐 CRT 刷新。
- 调试接入：`--debug-server=<port>` 启动 C VM 的 SLDP（NDJSON over TCP）供 VSCode DAP 连接；`--debug` 是 verbose 跟踪（不同通道）。

## 5. 版本策略（分组件独立）

版本**分开管理**：本体（Front / C VM / 宿主三锚点一起改）· VSCode · 插件 · 包，各自独立演进。改哪个组件只递增谁。

| 端 | 锚点 | 现值 |
|----|------|------|
| Front | `simple_language/source/CLI/CommandExecutor.cs` → `VersionString` | 0.0.68 |
| C VM | `csimple_lang/src/cli/cli_version.h` → `SLVM_VERSION_*` | 0.0.68 |
| 宿主 | `SlangAllInOne/SlangAllInOne.csproj` → `<Version>` | 0.0.68 |
| VSCode | `slang_vscode_plugin/package.json` + `package-lock.json`（双字段） | 0.0.67（独立） |
| 插件 | `plugin/<id>/plugin.jsonc` → `plugin.version` | 各自独立 |
| 包 | `SLangCore/Lib/**/*.jsonc` → `buildVersion` 等 | 各自独立 |

版本查看/改写优先走后管 `tools/docs-web/admin-server.js`（`/admin` 版本管理页，自动留痕）。正式发布 `release-slang.ps1 -Version <X.Y.0>`：Y+1、Z 归零，锚点同步。
