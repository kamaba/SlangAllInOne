# 风险、待办与验收

> 本文汇总 SLang × WebUI 集成的**风险点、待办项、与既有模块的关系、验收标准**。
> 设计与实现细节见 `00`~`06`。

---

## 1. 风险清单

### R1 · VM 并发重入（最高优先级）
- **问题**：webui 默认每个 UI 事件在独立线程调用回调；SLang VM 是否支持多线程并发执行
  同一实例**未验证**。并发重入可能破坏 VM 内部状态。
- **缓解（P1 默认）**：`webui_set_event_blocking(window, true)`（或全局
  `webui_set_config(ui_event_blocking, true)`）把事件串行化，`createCallback` 回调节流点
  重入是单线程的，与当前 VM 模型兼容（见 `02` §4）。
- **残留**：`multi_client`（Web 应用多客户端并发）模式需要 VM 真正线程安全 → 列为后续。

### R2 · FFI 回调签名约束
- webui 回调 `void(*)(webui_event_t*)`：事件指针 → `ptr`，返回 `void` → sig `"ptr->void"`。
- SLang `createCallback` 要求 C 侧回调形参全宽（`int64_t`/`float`/`double`），`ptr` 即 64 位，
  满足（见 `ffi.md` §2.4）。
- **待验证**：`createCallback` 是否支持**非静态方法 / lambda** 直接注册。若不支持，P1 用
  显式静态方法（见 `03` §4.1），lambda 语法糖后续补。

### R3 · 仅 x64
- SLang FFI 仅 x64（见 `ffi.md` §9）。webui 同 x64 构建无碍；但意味着 SLang+WebUI 目前
  仅支持 x64 平台的桌面程序。

### R4 · webui 版本漂移
- vendored `2.5.0-beta.4`（beta）。webui API 在 2.x 相对稳定，但 beta 阶段可能变动。
- **防护**：SLang 只经 `_sl` 扁平封装与 `getArg*`/`return*` 访问 webui，不直接暴露
  `webui_event_t` 布局；升级 webui 时只需改 `cvm_webui.c` 内部转发，SL 层 API 稳定。
- 升级前复核 `webui.h` 差异，必要时更新 `01-webui开源库调研.md` 的 API 清单。

### R5 · 浏览器可用性
- webui 运行依赖「系统已装浏览器」。无浏览器环境（如纯服务器/容器）下 `webui_show` 失败。
- **缓解**：`webui_browser_exist(browser)` 可探测；失败走 SLang 兜底（返回 false），
  程序可降级为纯后端或报错提示。桌面场景通常满足。

### R6 · 字符串缓冲生命周期
- `get_string_at` 返回 webui 内部缓冲（回调期有效）；`webui_script_sl` 用线程局部缓冲。
- 在 `ui_event_blocking=true` 串行模式下安全；放开多线程时需改用 per-call 分配（见
  `04` §5）。

### R7 · WebView2 依赖（仅 Windows WebView 模式）
- `webui_show_wv` 需目标机 `WebView2Loader.dll`。P1 默认浏览器模式不需要；WebView 形态
  列为可选，文档注明前置依赖。

## 3. 与既有模块的关系（何时用哪个）

| 需求 | 推荐 |
|---|---|
| 桌面 GUI，本地程序 + 系统浏览器 | **SLang.WebUI**（本方案） |
| 后端 HTTP/WS 服务，单独起浏览器访问 | `SLang.Server`（HttpServer / WebSocketServer） |
| 重型桌面 UI、完整 widget 工具包 | `SLang.QT`（依赖 Qt 运行时） |
| Canvas / 图形绘制（非窗口） | `SLang.Render` |
| 本地 GUI + 后端业务逻辑 | WebUI 弹窗 + Server 路由（进阶联动） |

- WebUI 与 Server **互补**：WebUI 解决「本地弹浏览器作 GUI」，Server 解决「网络服务」。
  二者可组合但 P1 不强制。
- WebUI 与 QT **互斥选型**：都做桌面 UI，但 WebUI 轻量（浏览器渲染）、QT 重（工具包）。
  新桌面项目优先 WebUI（无重型运行时依赖、MIT 可分发）。

## 4. 验收标准

### 功能验收
1. `T01` 能弹出浏览器窗口并显示 HTML；
2. 点击按钮 → SLang 处理函数被触发 → `returnString` 结果正确回传 JS 并显示；
3. 多窗口正确创建/关闭；`webui_wait()` 在所有窗口关闭后返回；
4. `win.script("return 6*7;", 5)` 取回 `"42"`；
5. Kiosk / 全屏 / 尺寸 / 位置属性生效。

### 健壮性验收
6. `webui_lib.dll` 缺失时，程序不崩溃，相关 API 走兜底返回零值/空串；
7. `webui_clean()` 后无资源悬空（进程退出干净）；
8. 串行事件模型下连续多次点击无 VM 异常（R1）。

### 合规验收
9. 文档齐备（`00`~`07` + 实现后 `WebUI.md`），同步 `md/INDEX.md`；
10. 版本遵循 R17 四端统一（模块自身不另立版本号）；
11. 新文件 UTF-8（R16）；核心 VM 无平台代码（R3）；
12. vendored webui 保留 MIT 版权，可随官方包分发（无 GPL 红线）。

## 5. 关键决策回顾（供评审）

| 决策 | 选择 | 理由 |
|---|---|---|
| 接入形态 | FFI 静态绑定（同 Mysql） | 零开销、预载、兜底 |
| 原生库 | 内嵌 webui.c（MIT） | 自包含、可随包分发 |
| 回调 | 原生 trampoline + bind_id 映射 + createCallback 重入 | 规避运行时代码生成 |
| 线程 | 默认 `event_blocking=true` 串行 | 规避 VM 并发重入（R1） |
| 命名空间 | `SLang.WebUI` | 与 Mysql 同构 |
| 模块名 | `SLangWebUI` | 与 `SLangMysql` 同构 |
