## 1. 与 UI 的分工

2D 渲染和 UI 都画 QUAD，但职责不同：

| 维度 | 2D 渲染（本章） | UI（第 08 章） |
|---|---|---|
| 所属 | 游戏世界中的精灵 / 地图 / 特效 | 交互层：按钮 / 面板 / 文本 |
| 坐标 | 世界 XY 平面（`Float32_3`，z=0） | 屏幕 / 画布空间（`Float32_2`） |
| 变换 | 普通 Transform（或 RectTransform 仅作尺寸用） | RectTransform（锚点 / pivot） |
| 输入 | 世界拾取（第 03 章 Ray） | UI 命中优先（第 08 章） |
| 相机 | 2D 正交相机（≈`setCamera` 的 l/r/b/t） | 独立 UI layer / UI 相机 |
| 合批 | 与 3D 共用合批器，按贴图 / 材质分组 | 独立 QUAD 批次，按层级顺序提交 |

简单判据：**能被角色碰撞、受相机移动影响的是 2D 渲染；始终贴屏、需要点击的是 UI。**

## 2. Render 侧可用基础【已落盘】

| 能力 | 常量 / 签名 | 说明 |
|---|---|---|
| 四边形网格 | `MESH_QUAD = 1` | 精灵的基本绘制单元 |
| 三角 / 自定义网格 | `MESH_TRIANGLE = 0` / `MESH_CUSTOM = 4`（slot 4..7） | 自由多边形 / 动态网格 |
| 动态顶点上传 | `pipe.uploadMesh(slot, ptr, n)` | 合批后写入合并顶点（第 05 章） |
| 动画模式 | `ANIM_NONE = 0` / `ANIM_HUE_CYCLE = 1` | `setAnimated(mode, speed)` |
| 相机 | `pipe.setCamera(cullMask, l, r, b, t)` | l/r/b/t 即**正交边界**，天然适配 2D |
| 透明段 | `queue >= 2500` 走 `renderShaderSegments`（后→前混合） | 2D 精灵几乎都走透明段 |
| 贴图 | `Texture.load` + `Material.setTexture`（需 `SLangImage`） | — |
| 上屏 | QLabel.setPixmapRgba | RenderTest 已验证 |

Render 侧**没有**：SpriteRenderer、Tilemap、SortingLayer / Order in Layer、精灵图集管理、像素完美相机封装、2D 物理。这些由本模块定义。

## 3. 2D 节点模型【设计稿】

```
GameObject "Player"
  ├─ Transform            ← position.xy 是屏幕位置，z 通常是 0 或小值用于排序
  ├─ SpriteRenderer       ← 贴图 + 颜色 + 翻转
  ├─ BoxCollider          ← 第 11 章（z 厚度设 0 或忽略）
  └─ Rigidbody            ← 第 12 章（重力设 (0,-g,0)，锁定 z 位移）
```

### 3.1 SpriteRenderer

```sl
public class SpriteRenderer extends Component
{
    public Texture texture
    public Material material            # 建议共享，便于合批
    public Float32_2 size               # 世界单位尺寸
    public Float32_2 pivot = Float32_2( 0.5f, 0.5f )
    public bool   flipX = false
    public bool   flipY = false
    public int    sortingLayer = 0
    public int    orderInLayer = 0
    public Float32 colorAlpha = 1.0f

    public void setSprite( Texture t )
    public void setFlip( bool x, bool y )
}
```

### 3.2 SortingLayer 与 Order in Layer

Unity 用「SortingLayer → Order in Layer → 深度」决定 2D 绘制顺序。本模块映射到 Render 已支持的排序输入：

| 引擎概念 | 映射 | 状态 |
|---|---|---|
| SortingLayer | 独立排序层表（设计稿），每层分配一个 queue 基值 | 设计稿 |
| Order in Layer | queue 基值 + order，写入 `RenderObject.setQueue(int)` | 门面已落盘 |
| 同层同 order | 用 `z` 值微调（Render 的绘制项有 z 参数，透明段后→前排序） | 门面已落盘 |
| 不同贴图 | 合批键分裂（第 05 章键分量 7） | 已定规则 |

建议取值：不透明 2D 元素 `queue < 2500`；透明精灵 `queue >= 2500`（绝大多数 2D 场景）；UI 用单独区间，不与 2D 精灵混排。

### 3.3 图集与合批

- 同一张贴图 + 同一材质 + 同 queue 的精灵 → 一个 RenderObject 批次（顶点合并 + `uploadMesh`）；
- 每个精灵用独立贴图 → 每个精灵一个批次，draw call 会线性增长；
- 因此大量精灵应使用**图集**：把多张小图合成一张大贴图，各精灵只改 UV；图集切分数据由业务侧维护，Render 侧只需要一张 `Texture`；
- 透明精灵的排序与合批天然冲突：同批内对象共享绘制顺序，跨排序层的精灵必须拆批。

## 4. 2D 相机【设计稿，基于已落盘门面】

`pipe.setCamera(cullMask, left, right, bottom, top)` 的四个边界就是正交相机参数：

```sl
# 设计稿：建立 16:9 正交世界，1 单位 = 100 像素
Float32 halfH = 5.4f
Float32 halfW = halfH * 16.0f / 9.0f
pipe.setCamera( layerMask2D, -halfW, halfW, -halfH, halfH )
```

2D 相机节点约定：

- 相机 Transform 只在 XY 移动，z 固定；
- `cullMask` 只开 2D 精灵所在 layer，不含 UI layer；
- 需要「像素完美」时，把正交边界对齐到整数像素（宽高比 / 缩放取整），避免采样抖动；
- 多相机 depth 规则沿用第 06 章。

## 5. 2D 物理与碰撞

复用第 11 / 12 章，只是把运动约束在 XY 平面：

| 项 | 2D 约定 |
|---|---|
| Collider | `BoxCollider` / `SphereCollider`，z 厚度忽略或设 0 |
| Rigidbody | `useGravity = true` 但重力向量为 `(0, -g, 0)`；velocity.z 恒 0 |
| 固定步长 | 与 3D 共用 `fixedUpdate` 累加器（第 09 章） |
| 变换同步 | 物理写 Transform.xy，渲染插值后参与合批（第 12 章 §5） |
| 拾取 | `Ray` 起点由 2D 相机 `screenPointToRay` 给出，与 z=0 平面求交（第 03 / 06 章） |

## 6. Tilemap【设计稿】

```sl
public class Tilemap extends Component
{
    public Texture atlas
    public int    width, height          # 格子数
    public Float32 cellSize = 1.0f
    public Array<int> tiles              # 每格图集索引，-1 = 空

    public void setTile( int x, int y, int index )
    public int  getTile( int x, int y )
}
```

绘制策略：**整张地图作为一个动态网格批次**（所有可见格子顶点合并，`uploadMesh` 一次），而不是每格一个 RenderObject。只有视口内的格子参与顶点生成（简单裁剪：格子中心是否在相机正交边界内）。

## 8. 已知坑与注意

1. **UI 与 2D 必须分层**：把 UI 挂到 2D layer 会被 2D 相机收集，出现「UI 跟着镜头跑」；用独立 layer + cullMask 隔离。
2. **透明精灵几乎都要 `queue >= 2500`**：否则进入不透明段，Alpha 混合不生效（Render 的规则，第 05 章）。
3. **排序与合批冲突**：Order in Layer 不同的精灵不能合批；用图集只能减少贴图分裂，不能消除排序分裂。
4. **`setRotationZ` 之外没有 2D 专用旋转**：精灵翻转用顶点 UV 处理（`flipX/flipY`），不要靠负 scale（可能导致背面剔除或法线翻转）。
5. **正交边界要跟宽高比一致**：`l/r/b/t` 比例与窗口不符会拉伸；窗口尺寸变化时重算边界。
6. **贴图依赖 `SLangImage`**：`Texture.load` 失败会让精灵变纯色或完全不可见，先确认模块引用与 `import SLangImage;`。
7. **~~2D 组件尚未落盘~~ → P7 引擎层 v1 已落盘（2026-11-16）**：`SpriteRenderer`/`SortingLayers`/`Tilemap` + `RenderSystem.collect2D/sync2D` 可用；剩余边界见 §0 表（翻转 UV、图集 UV、uploadMesh 合批提交）。
8. **Behaviour 子类方法体内含 while 循环时自身字段读/常量比较失效**（Sim2DTest D9h/D10 实证）：`tileCount/bake` 的循环逻辑放 static 方法承载（`tileCountOf/bakeOf`，无 `this` 无污染）；循环内对**常量表达式**的比较（`t > 0 - 1`）恒真——两侧一律局部变量（`oq > iq` 形态）。详见 doc/10 §6 坑汇总。

## 9. 2D 游戏类型与宽高比适配【已落盘，2026-11-19】

### 9.1 节点分离约定

2D 场景按「批量内容单节点、独立元素实体节点」分离：

```
Scene
 ├─ Parallax/Background     Tilemap 或精灵，多排序层，ParallaxLayer 差速
 ├─ Terrain (Tilemap 节点)  一个 GameObject 挂 Tilemap（地图不逐格建节点）
 ├─ Entities                每对象一个 GameObject + SpriteRenderer + Collider/Rigidbody
 └─ FX / UI                 Effect 组件 / UIBehaviour
```

- 地形碰撞不逐格建节点：`TileColliderBaker.bakeRowColliders(scene, tm, parent, prefix)` 把同行连续实心格合并成段，每段一个子 GameObject + `BoxCollider`（段 center/size 见源码头注释）；
- tile 前后靠 `SortingLayers`（8 层 × order 0..99）控制。

### 9.2 宽高比适配（CameraRig2D）

`RenderSystem.viewSize` 语义 = 视口纵向半高（Unity orthographicSize），横向半宽 = viewSize × aspect（aspect = pixW/pixH）。`CameraRig2D` 在此之上提供三档适配：

| fitMode | 语义 | 适用 |
|---|---|---|
| 0 MatchHeight（默认） | 纵向视野恒定 = `refSize`，横向随窗口扩展/裁切 | 横版卷轴、俯视 RPG |
| 1 MatchWidth | 横向视野恒定 = `refSize`，纵向随窗口变化 | 竖屏、固定屏 |
| 2 PixelPerfect | `scale = floor(像素高 / refPixelHeight)`（下限 1），1 世界单位 = 1 参考像素 | 像素风 tile 游戏 |

用法（每帧一次）：

```sl
RenderSystem rs = RenderSystem()
rs.setPixelSize( 1280, 720 )      # 宿主/测试无管线形态；有管线时 init/resize 自动登记
CameraRig2D rig = CameraRig2D()
rig.fitMode = 0
rig.refSize = 5.4f
rig.target = player               # 跟随目标（null = 只适配）
rig.smoothTime = 0.1f             # 0 = 硬切；>0 = 指数平滑时间常数 τ
rig.useBounds = true              # 地图边界钳制（视野大于地图自动居中）
rig.boundMinX = 0.0f
rig.boundMaxX = 120.0f
rig.boundMinY = 0.0f
rig.boundMaxY = 18.0f
# 每帧：
rig.update( rs, dt )              # 写 rs.cameraCenter / rs.viewSize
rs.collect2D( scene, cullMask )
rs.sync2D()
# 传送/切目标后：rig.snap() 下一帧硬切
```

### 9.3 Tilemap 网格语义（俯视/网格类）

```sl
Int32 cx = tm.cellXAtWorld( wx )      # cell = floor((world - origin) / cellSize)
Int32 cy = tm.cellYAtWorld( wy )      # 越界格返回计算值（负数/超界），inBounds 判定
tm.setTileFlag( tileIndex, 1 )        # tile 属性表（按图集索引；bit0 = solid）
bool solid = tm.isSolidAt( x, y )     # tile >= 0 且属性 bit0 == 1；空格恒非实心
```

### 9.4 视差背景层（ParallaxLayer）

挂背景节点，`apply(camCenter)` 按系数差速移动：`pos = base + (cam - anchor) * (1 - f)`。

- f = 1 → 不动（随世界，等同前景）；f = 0 → 完全贴屏（无限远）；0<f<1 → 屏幕上以 f 倍相机位移差速。
- 建层时先摆好节点位置，首次 `apply` 自动 `captureBase()`（或显式调用）；
- 写的是 local 位置：多层根节点直挂 Scene 下，或父节点恒在原点。

### 9.5 游戏类型 → 能力矩阵（引擎不分游戏类型，只供配置组合）

| 大类 | 相机 | tile 用法 | 物理/ui | 需要的件 |
|---|---|---|---|---|
| A 横版卷轴 | CameraRig2D MatchHeight + 跟随钳制 | 地形 + TileColliderBaker 碰撞 | 重力 Rigidbody | ParallaxLayer 背景 |
| B 俯视网格（RPG/战棋/SLG） | CameraRig2D MatchHeight/固定 | 地形 + worldToCell 逻辑坐标 + tile 属性表 | 无重力/格步自写 | UI 层（第 08 章） |
| C 自由布局（弹幕/塔防/经营） | CameraRig2D MatchWidth 或固定 | 可不用 Tilemap | 按玩法 | 纯 SpriteRenderer 组合 |

单屏街机 = B 类去卷动 + 地图一屏的退化形态，不单列。
