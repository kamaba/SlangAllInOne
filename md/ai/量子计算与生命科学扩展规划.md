# SLang 向「量子计算」与「生命科学」扩展规划书

> 文档性质：方向规划（设计/AI 类，非使用者文档）。落点 `md/ai/`。
> 编写日期：2026-11-22。
> 依据：对 `SLangCore/Lib`、`csimple_lang/src/vm`、`plugin/`、`unity/` 的实盘勘察。
> 读者：决定方向取舍的人 + 后续实现者。

---

## 0. 一句话结论

两个方向的**共同地基只有三块**：① 复数数值体系、② 更高精度与线性代数求解、③ 强字符串/字节原语。
这块地基补齐后，量子方向主要叠「门/线路/测量 + 模拟后端」，生命科学方向主要叠「生物格式 + 序列原语 + 比对/统计」。
两者都能站在已有的 `Tensora`（张量 + 自动微分 + SIMD/GPU）、`Std.IO`、`StatsPlot` 上，不需要重造编译器。

现状一句话：**量子相关零基础（复数都没有），生命科学有数据管线底座但字符串与生物格式是瓶颈**。

## 1. SLang 现有什么（家底）

| 能力 | 现状 | 对两方向的价值 |
|---|---|---|
| 类型系统 | `Int8~64`/`UInt8~64`/`Float8/16/32/64`/`bool`/`string`；`Array<T>`/`List<T>`/泛型/`class`/`data`/`enum`；运算符重载（`_add_` 等） | 够用；**缺复数、缺 `char`** |
| 数学库 | `Mathf/Mathd/Mathh` 标量三角幂对；向量/矩阵 `Float32_3x3/4x4`、`Matrix`、`Quaternion`；`BigNumber/BigDecimal/Factor` | 实数够用；**缺复数、缺本征值/SVD/线性求解** |
| 张量与 AI | `SLang.Tensora`：60+ 类，Tensor/Shape/dtype/广播/matmul/归约/softmax/Autograd/Transformer/CNN/Optimizer；`sl_tensora_lib.dll` CPU SSE2/AVX2 + CUDA 运行期解析 | 两方向**最强可复用资产**；**dtype 无复数、无 F64** |
| 随机数 | `Core.Random`（LCG）；`Tensora.Rng`（bernoulli/gumbel/normal/shuffle） | 量子测量采样、生统抽样可直接用 |
| 字符串/文本 | `string` 是 UTF-8 字节串，仅 `format/length/front/end/slice/...` 8 个方法；补救靠 `Text.RegExp`/`StringBuilder`/`Utf8Codec` | **生命科学最大短板**：无 `split/indexOf/replace/trim`、无码点接口 |
| 文件与数据 IO | `Std.IO.File/FileStream`、`Core.IO.ByteBuffer/ByteStream/BinaryCodec`；`Text.Json/Csv/Xml/Yaml/Toml` | 生物格式解析的起点；**无 FASTA/FastQ/PDB** |
| 统计 | `SLang.StatsPlot`：DataFrame(CSV)、mean/median/sd/quantile/correlation、6 图表 | 生统起点；**仅 Float32、仅数值列、无字符串分组列** |
| 并发/隔离 | `Coroutine`、`Isolate`（独立 VM + 消息深拷贝） | 可为批量模拟/比对做并行 |
| 扩展机制 | 模块(slb/jsonc)、FFI 三路(`FFI.Library`/`@DllImport`/`@DllStaticImport`)、systemCall(`cvmFunction` 可 `Dll!symbol`)、插件六件套(frontendNative/ABI)、Unity UPM 直连 | **机制齐全，新领域无需改编译器** |

## 2. 共用地基（P0，两个方向都先做）

优先级最高，因为两个方向都卡在这里。

> **进度（2026-11-22）：§2.1 复数数值体系已实现** —— `SLang.Complex64`/`Complex32`/`MathComplex`
> 三类型 + `math_lib.dll` 的 46 个 `mathc_*` 原生算子 + FFI/纯 SL 双路径，
> `ComplexTest` 41/0 通过（两条路径均验证）。详见 `md/lib/Math/Complex.md`。
> 仍待办：§2.2 F64/线性代数求解、§2.3 字符串原语增强。

### 2.1 复数数值体系 —— 量子方向的硬阻塞

- 新增 SL 类型 `Complex32` / `Complex64`（实部虚部为 `Float32`/`Float64`），提供 `+ - * /`、共轭、模、幅角、指数；按现有运算符重载约定实现（`_add_` 等，`operator.md` 已有先例）。
- `math_lib.dll` 增加复数算子（`mathc_*`：cadd/cmul/cdiv/cabs/cexp/csqrt…），SL 侧 `@DllStaticImport` + 纯 SL 兜底（照 `Mathd.sin` 的写法）。
- `Tensora` 的 `Dtype` 增加 `COMPLEX64/COMPLEX128`，`sl_tensora_lib` 增加复数 matmul/归约 kernel。
- **收益**：量子态幅度、傅里叶/频域分析（生统与结构生物学也用）一次性解决。

### 2.2 精度与线性代数求解

- `Tensora` 增加 `F64` dtype（现仅 F32/F16/BF16）。
- 补本征值分解、SVD、线性方程组求解（量子可观测量、PCA/聚类都要用）。可先接成熟 C 库（LAPACK 精简子集）走 FFI，不必自研。

### 2.3 字符串/字节原语增强 —— 生命科学的硬阻塞

- `string` 补 `indexOf/lastIndexOf/split/replace/trim/toLower/toUpper/startsWith/endsWith`，并加 `char` 或码点遍历接口。
- 提供**字节切片视图**（零拷贝 slice）与定长 `k-mer` 迭代器，避免序列分析里海量小字符串分配。
- **收益**：k-mer 切分、序列模式匹配、多序列比对从"极其笨重"变为"自然表达"。

> 这三项做完，再分别叠方向层。下面的 P1/P2 都以 P0 为前提。

## 3. 方向一：量子计算

### 3.1 分层补充清单

| 层 | 要补的东西 | 建议机制 |
|---|---|---|
| L0 数值 | 复数、复数张量、F64、线性求解（见 §2） | SL 模块 + FFI（复用 `math_lib`/`sl_tensora_lib` 模板） |
| L1 表示 | `Qubit`、`StateVector`（态矢量）、`DensityMatrix`（密度矩阵）、`PauliString` | 纯 SL 模块（内部结构用 `Tensor`/`Complex64`） |
| L2 门与线路 | 单/双/三比特门（H/X/Y/Z/S/T/Rx/Ry/Rz/CNOT/CZ/Toffoli/SWAP）、`QuantumCircuit`（add/measure/depth）、门矩阵与张量收缩 | 纯 SL 算法层 + 少量 FFI 热点 |
| L3 测量与噪声 | 采样（复用 `Rng.bernoulli`）、期望值、`Pauli` 测量；噪声通道（bit-flip/phase-flip/depolarizing）、密度矩阵演化 | 纯 SL + `Rng` |
| L4 算法库 | 量子傅里叶变换、Grover、Shor 核心、VQE/QAOA（复用 `Tensora.Optimizer`/Autograd）、HHL | 纯 SL 模块 |
| L5 后端 | ① 纯 SL 模拟（教学/小规模）；② 高性能 `sl_quantum_lib.dll`（态矢量/张量网络，参考 `sl_tensora_lib` 多后端骨架）；③ 外部 SDK 接入（Qiskit/Cirq/PennyLane） | FFI + 插件六件套 |

### 3.2 生态接入策略（关键取舍）

- **自研模拟优先**：先用 P0 复数 + Tensora 做纯 SL / 原生算子模拟，保证语言自身可独立演示量子线路，不依赖外部 Python。
- **外部 SDK 走插件**：若要接真实量子硬件/成熟模拟器，用 `plugin/` 的六件套模式（参 `csharp_mono`/`java_hotspot`）：原生 C 包装 + frontendNative 编译契约 + ref module（`SLang.Quantum.Qiskit.*`），比新增 system call 更隔离、可独立发布。
- **规模现实**：纯态矢量模拟随比特数指数增长；L5 的 `sl_quantum_lib` 要支持张量网络/矩阵积态才能上规模，这一步投入最大，建议放到 VQE 等算法验证之后再决定。

## 4. 方向二：生命科学

### 4.1 分层补充清单

| 层 | 要补的东西 | 建议机制 |
|---|---|---|
| L0 数据格式 | FASTA / FASTQ / PDB / GenBank 解析器 → 结构化模型（`Sequence`、`Residue`、`Structure`） | 纯 SL 模块，基于 `Std.IO.File` + `ByteBuffer` + `Text.Csv` 经验 |
| L1 序列原语 | DNA/RNA/Protein 序列类型、k-mer 迭代、反向互补、转录/翻译、密码子表、质量值(FastQ) | 纯 SL + §2.3 字符串增强；热点 k-mer 走 FFI |
| L2 比对与搜索 | 双序列比对（Needleman-Wunsch 全局 / Smith-Waterman 局部）、多序列比对、BLAST 式种子扩展、编辑距离 | 纯 SL 算法 + `sl_bio_lib.dll` 热点（动态规划内核） |
| L3 统计 | `StatsPlot` 扩 F64 + 字符串列分组；生统常用：生存分析、差异表达、聚类、PCA（用 §2.2 线性代数） | SL 模块 + FFI |
| L4 结构生物学 | PDB 坐标 → 3D 模型，复用 `SimGameEngine` 渲染管线做分子可视化；距离矩阵、RMSD | SL 模块 + 复用渲染引擎 |
| L5 ML for biology | 蛋白/基因序列分类、结构预测实验：直接复用 `Tensora` 的 Embedding/Transformer/Trainer | 复用 Tensora，仅补数据加载器 |

### 4.2 生态接入策略

- **纯 SL 起步**：解析器和比对算法先用 SL 实现——它们本质是字符串 + 动态规划，正好验证 §2.3 的字符串增强是否够用。
- **性能热点下沉**：比对动态规划、k-mer 计数这类热点，仿 `math_lib`/`sl_bio_lib` 走 FFI（`.slffi.json` 契约 + `ffi-check`），保留纯 SL 兜底。
- **大型生信工具链走插件**：BLAST、SAMtools、Bioconductor 这类成熟工具，用插件六件套承载原生运行时，ref module 提供 SL 门面。
- **差异化卖点**：SLang 已有渲染引擎，可把「序列 → 结构 → 3D 可视化」做成一条龙，这是多数脚本语言没有的。

## 5. 实施路径（建议排期）

| 阶段 | 内容 | 交付物 | 判定 |
|---|---|---|---|
| **P0 地基** | 复数类型/库、Tensora 复数+F64+线性求解、字符串原语 | `SLang.Complex` 模块、Tensora dtype 扩展、`String` 方法集 | 复数 matmul 与 F64 归约测试通过；字符串基准用例通过 |
| **P1 量子 MVP** | L1 表示 + L2 门/线路 + L3 测量；纯 SL 模拟 | `SLang.Quantum` 模块 + QuantumTest | 3~5 比特 grover/QFT 线路跑通，测量分布符合预期 |
| **P1 生信 MVP** | L0 FASTA/FastQ 解析 + L1 序列原语 + L2 双序列比对 | `SLang.Bio` 模块 + BioTest | 真实 FASTA/FastQ 文件解析 + NW/SW 比对结果对齐参考实现 |
| **P2 性能** | `sl_quantum_lib`、`sl_bio_lib` 原生算子；噪声模型；StatsPlot F64/字符串列 | 两个原生库 + SIMD/多后端 | 与纯 SL 实现位级一致，性能有量级提升 |
| **P3 生态** | 外部 SDK 插件（Qiskit / 生信工具链）、结构可视化、VQE/ML 案例 | 插件包 + 示例工程 | 插件可独立发布，示例端到端可跑 |

## 6. 扩展机制选型速查

| 场景 | 用什么 | 现成范本 |
|---|---|---|
| 算法/数据模型（纯逻辑） | 纯 SL 模块（jsonc + `.sl` → slb） | `Math/Random.sl`、`Tensora/*.sl` |
| 高性能算子（门模拟、比对内核） | 原生库 + FFI（`@DllStaticImport` + `.slffi.json`） | `math_lib`、`sl_tensora_lib`、`sl_image_lib` |
| VM 级热点（对象/数组直读写） | systemCall + `cvmFunction: "Dll!symbol"` | `SystemMathMat3Mul`、`mathvm_sinf` |
| 接入大型外部运行时/SDK | 插件六件套（frontendNative + ABI + ref module） | `csharp_mono`、`java_hotspot` |
| 与宿主引擎深度集成 | UPM/宿主直连（C++ 绑定面） | `SlangAllInOne/unity/` |

**原则**：先用纯 SL 把领域模型跑通，再把实测热点下沉 FFI，最后才考虑插件/VM 级改动；不为了"看起来高级"而过早改编译器。

## 7. 风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| 复数改动面大 | 类型系统 + 数学库 + Tensora dtype + kernel 四处联动 | 先做独立 `Complex` 模块，Tensora 复数 dtype 放 P0 末；用标准算子测试逐层锁死 |
| 量子模拟规模天花板 | 态矢量指数增长，10 比特以上即吃紧 | 明确"教学/算法验证"定位；上规模留给张量网络后端（P3） |
| 字符串增强牵一发动全身 | `string` 是核心类型，方法语义要稳 | 新增方法保持 UTF-8 字节语义，Unicode 码点接口单独放 `Utf8Codec` 扩展，不改底层表示 |
| 生信工具链版权/依赖 | BLAST 等有许可与原生依赖 | 优先纯 SL 自研常见算法；外部工具仅以插件形式可选接入 |
| StatsPlot 精度债 | 现仅 Float32、无字符串列 | 生在 P2 一次性补 F64 + 分类列，避免两处重复改 |
| 方向聚焦 | 同时铺两条线风险高 | 建议 **P0 共用地基 → 二选一做 P1 MVP → 再开另一条** |

## 8. 验收标准（总）

- [ ] `SLang.Complex`：复数四则/共轭/模/指数测试通过，且与 `Float64` 精度一致。
- [ ] `Tensora`：`COMPLEX64/128` + `F64` 的 matmul/归约/softmax 测试通过；求解器与参考实现对齐。
- [ ] `String`：常用方法集齐备，序列 k-mer 迭代有基准用例。
- [ ] `SLang.Quantum`：多门线路 + QFT/Grover 跑通，测量分布统计正确。
- [ ] `SLang.Bio`：真实 FASTA/FastQ 解析 + NW/SW 比对对齐参考实现。
- [ ] 原生算子（`sl_quantum_lib`/`sl_bio_lib`）与纯 SL 实现位级一致，跨平台库布局正确。
- [ ] 各方向至少 1 个端到端示例工程 + 使用者文档（`md/lib/` 下）+ 模块测试挂入统一测试入口。

## 9. 待定 / 需要拍板

1. **优先级**：量子与生信先做哪个 MVP？（建议先量子，因复数地基复用性更强、演示效果好；若有无机化学/生物背景资源则先生信。）
2. **精度策略**：量子是否一步到位上 `COMPLEX128 + F64`，还是先 `COMPLEX64` 验证？（影响 P0 工作量）
3. **外部 SDK**：量子是否必须接真实硬件/云后端，还是先纯模拟？（决定 P3 插件是否必要）
4. **团队投入**：本规划按"1~2 人持续投入"估算，若仅业余时间建议只做 P0 + 单方向 MVP。
