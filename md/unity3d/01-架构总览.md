# 01 · 架构总览

> 把 SL 当 Unity 热更脚本的**总体架构、数据流、与 Unity 脚本后端（Mono / IL2CPP）的关系**。
> 落地细节见 `02`~`13`。

---

## 1. 三明治模型

```
┌──────────────────────────────────────────────────────────────────────┐
│  Unity 引擎 (C++)  ←→  Unity C# 脚本层 (Mono / IL2CPP)                │
│     │                       │                                          │
│     │ 引擎对象 (GameObject/Transform/Component...)                     │
│     ▼                       ▼                                          │
│  ┌──────────────────────────────────────────────────────────┐         │
│  │  宿主桥接层 (SlangUnityBridge.cs)                          │         │
│  │   P/Invoke / IL2CPP extern "C" → csimple_lang_dll         │         │
│  │   - 装载 SLB / 内存 JSON                                   │         │
│  │   - 注册 "Unity 宿主回调" (host function table)            │         │
│  │   - 转发 Unity 生命周期 (Update/FixedUpdate/OnDestroy)     │         │
│  └──────────────────────────────────────────────────────────┘         │
│            │  dll 边界 (C ABI)                                        │
│            ▼                                                           │
│  ┌──────────────────────────────────────────────────────────┐         │
│  │  C VM (csimple_lang, C99→C++ 原生插件)                     │         │
│  │   - 解释执行 SLIR（JIT 在 IL2CPP/iOS 强制关闭，见 08）      │         │
│  │   - systemCalls：SL → Unity 引擎调用（反向桥，见 05）       │         │
│  │   - SLB 装载 / mtime 守卫热更（见 04）                      │         │
│  └──────────────────────────────────────────────────────────┘         │
│            ▲                                                           │
│            │  SL 源码 (.sl) → Front 编译 → SLB / 内存 JSON             │
└────────────┼──────────────────────────────────────────────────────────┘
             │
   ┌─────────┴──────────┐
   │  Slang Front (C#)   │  编译期：.sl → SLIR 包（可内存直传，见 03/04）
   │  slang compile --format binary+json
   └────────────────────┘
```

要点：
- **C VM 是 Unity 原生插件**（C++ 库），不是托管程序集——它独立于 Unity 的 Mono/IL2CPP 运行时存在。
- **宿主桥接层**是唯一跨越「托管（C#）↔ 原生（C VM）」边界的代码，封装 `csimple_lang_dll` 的宿主 API（`csimple_lang/md/cli.md`、`src/cli/cli.h`）。
- **绑定层**让 SL 脚本能操作 Unity 引擎对象，是 `MONO_INTEGRATION_DESIGN.md` 的「反向版」：那里是 SL 调独立 Mono 的 C#；这里 SL 调**宿主 Unity 自己的 C#**。

## 2. 两种执行链路

### 2.1 磁盘链路（包内运行 / 热更重装载）
```
slang compile MyHot.sl  →  out/export/MyHot/MyHot.module.slb  (+ .module.json 调试副本)
        │
Unity 运行时 FileWatcher 检测到 slb mtime 变化
        │
宿主桥接层 → cli_run_module_in_memory(json, base_dir, flags, args)  （或从磁盘重新装载）
```
- 热更核心 = `SLB_DESIGN.md` §7.4「读取优先 SLB」的 mtime 新鲜度守卫（2s 容差）。重编译后新 slb mtime 更新，VM 下次装载自动采用新包（`04` 详述）。

### 2.2 内存链路（开发期零落盘 / Editor 热写）
```
Unity Editor 内改 .sl → Front 编译 → 内存 JSON 文本
        │
cli_run_module_in_memory(json_text, base_dir, flags, program_args, arg_count)
        │  （借用字符串，调用期须保持有效；详见 03 §3）
        ▼
C VM 直接执行，跳过 module.json 写盘/读盘
```
- 复用 `cli_run_module_in_memory`（`csimple_lang/md/cli.md` 宿主 API 段），与宿主 `slang <工程>` 内存链路同源（`SLB_DESIGN.md` §7.1 memory 态）。

## 3. 与 Unity 脚本后端的关系

| Unity 后端 | 说明 | 对本整合的影响 |
|------------|------|----------------|
| **Editor / Development Mono** | Unity 自带 Mono（类 classic Mono） | 宿主桥接层走 P/Invoke；调试体验最佳 |
| **Standalone IL2CPP** | C# 经 IL2CPP 转 C++ 再 AOT 编译 | 宿主桥接层走 `extern "C"`（IL2CPP 不支持动态 P/Invoke 反射，但支持静态 `DllImport`/`extern`）；**JIT 必须关**（08） |
| **iOS（强制 AOT）** | 苹果禁止运行时生成代码 | C VM 不能 JIT；只能解释执行（`SL_JIT=0`） |
| **Android IL2CPP / Mono** | 同 Standalone 规则 | 同上 |
| **WebGL（wasm）** | Unity 用 Emscripten 编 wasm | C VM 已有 wasm 通道（`csimple_lang/md/WASM_BUILD.md`），可对齐复用 |

关键结论：**C VM 作为原生插件，其解释执行不受 Unity 后端切换影响**（IL2CPP 只影响「C# 宿主桥接层」的写法，不影响 C VM 自身）。唯一的硬性约束是 **JIT 在 IL2CPP/iOS 一律关闭**（见 `08`）。

## 4. 数据流（一次热更调用）

```
[开发] .sl 修改
   → Front 编译 → 新 SLB (mtime 新)
[运行] Unity FileWatcher 事件
   → 宿主桥接层 重新装载 SLB（或重编译+内存直传）
   → C VM 新建 isolate/执行域，跑新逻辑
   → SL 经 systemCall 调 Unity API（绑定层）操作 GameObject
   → 结果回传 SL；异常经 SL try/catch 或回抛 Unity
```

跨边界对象生命周期见 `05` §6（handle 表）；异常映射见 `05` §7 与 `MONO_INTEGRATION_DESIGN.md` §9。

---

## 5. 设计非目标（本次不做）

- 不改 C VM 的 opcode / IR / GC 主流程（R2、R15 不变）。
- 不把 SL 编译成 IL2CPP 能吃的 C#（那是另一条路线，本期不取）。
- 不做 SL 层的完整 Unity 物理/渲染替代——只做「脚本驱动既有 Unity 对象」的桥。
